Azure AI and machine learning

Azure combines hosted OpenAI and other frontier models with an enterprise-grade retrieval and agent platform. This step covers how to choose, build, and govern.

2. Models and deployments

  • Models are deployed into a Foundry or Azure OpenAI resource and called through endpoints. Deployment types include Standard (pay per token, regional or global), Provisioned throughput (reserved capacity for predictable latency) and Batch.
  • Use Microsoft Entra ID with managed identities rather than API keys where possible; disable key auth in production.
  • Use the model router or compare models in the catalogue to balance quality, latency and cost; regional quota and availability vary.
  • Fine-tuning and distillation are available for selected models; try prompting and retrieval first.

3. Retrieval with Azure AI Search

Azure AI Search provides indexing with built-in chunking and vectorisation, hybrid search with semantic ranking, and security trimming by user or group so retrieval respects permissions. Agentic retrieval can plan and run multiple sub-queries for complex questions. Pair it with Document Intelligence to extract structure from PDFs and forms.

  1. Land content in Blob Storage, SharePoint or databases.
  2. Index with chunking, embeddings and metadata (including ACLs).
  3. Retrieve with hybrid search and semantic reranking.
  4. Generate with citations; evaluate groundedness.

4. Agents

Foundry Agent Service hosts agents with tools (search, code interpreter, functions, MCP servers, other agents), threads and tracing. The Microsoft Agent Framework (successor to Semantic Kernel and AutoGen patterns) is the code-first option; Copilot Studio is low-code. Give each agent its own Entra identity with scoped permissions, log tool calls, and require approval for sensitive actions.

5. Azure Machine Learning

  • Workspaces, compute clusters, pipelines, registries and managed online and batch endpoints for custom ML.
  • MLflow tracking and model registry, responsible AI dashboard for fairness and explainability.
  • Use managed virtual networks and private endpoints for regulated data.
  • Databricks and Fabric are common partners for large-scale data and ML.

6. Safety, security and governance

  • Azure AI Content Safety: harm categories, prompt shields for jailbreak and indirect injection, groundedness detection, protected material detection.
  • Microsoft Defender for Cloud AI threat protection and Purview for data classification and governance.
  • Network isolation with private endpoints, customer-managed keys, and data-zone or regional deployments for residency.
  • Azure Policy can restrict models and regions; use evaluation and red-teaming tools in Foundry before release.
  • Cost: right-size the model, use batch and provisioned throughput deliberately, monitor tokens per feature.
PracticeBuild a Foundry app that answers questions over internal documents using AI Search with security trimming, add content safety, and trace a request end to end.
