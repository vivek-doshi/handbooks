Step 01 · Beginner · Provider-neutral concepts before you pick AWS, Azure, or GCP

Cloud fundamentals

Every provider uses different names for the same ideas. This step builds the shared vocabulary and mental model once, so the AWS, Azure and GCP steps feel like translation rather than new learning.

Service modelsShared responsibilityRegions and zonesIdentityCost basicsAI in the cloud

1. Service models and what you manage

Cloud is rented, API-driven infrastructure. The higher up the stack you go, the less you operate and the less control you have.

ModelYou manageExamples
IaaSOS, runtime, app, dataVirtual machines, block storage, virtual networks
CaaSContainers, app, dataKubernetes services, serverless containers
PaaSApp code and dataApp hosting, managed databases
FaaS / serverlessFunctions and configEvent-driven functions, workflows
SaaSConfiguration and usersEmail, CRM, AI assistants

Default to the highest-level service that meets your requirements, and drop down only when you need control, portability, or specialised performance.

2. Shared responsibility

The provider secures the cloud itself (data centres, hardware, the hypervisor, managed-service internals). You secure what you put in it: identity and access, data classification and encryption choices, network exposure, configuration, and application code. Most cloud breaches come from customer-side misconfiguration, such as public storage, over-privileged identities and leaked keys, not from provider failures.

3. Global infrastructure

  • Region: a geographic area with multiple data-centre groups. Choose by latency, data residency, service availability and price.
  • Availability zone (AZ): an isolated failure domain inside a region. Spread across at least two, preferably three, for high availability.
  • Edge locations: points of presence for CDN, DNS and acceleration.
  • Sovereign and partner regions: options for strict residency regimes such as the EU.

5. Identity and security first

  • Use a central identity provider with SSO and MFA; avoid shared accounts.
  • Grant least privilege with roles; prefer temporary credentials and workload identity over access keys.
  • Separate environments and workloads using accounts, subscriptions or projects.
  • Encrypt data at rest and in transit; manage keys with the provider's key service.
  • Enable audit logging everywhere and send it to a protected location.

6. Cost basics

Cloud is pay-as-you-go, so unmanaged usage becomes unmanaged cost. Learn the three levers early: right-size what you run, commit to steady usage for discounts (reserved capacity, savings plans, committed use), and use spot or preemptible capacity for fault-tolerant work. Tag every resource with owner, environment and cost centre, and set budgets with alerts. Data egress and idle resources are the usual surprises.

7. Where AI fits

Cloud AI comes in layers. Pick the lowest layer of effort that works.

LayerWhat you getUse when
Prebuilt AI APIsVision, speech, translation, document extractionThe task is common and a generic model is good enough
Foundation model platformsHosted LLMs, embeddings, guardrails, agents and retrievalBuilding generative AI features without training models
ML platformsManaged notebooks, training, tuning, pipelines, endpointsYou have your own data and need custom models
AI infrastructureGPUs and custom accelerators, high-speed networkingLarge-scale training or self-hosted inference
PracticePick a product you know. For each building block above, name the service you would use on one provider, and decide which AI layer it would need.
