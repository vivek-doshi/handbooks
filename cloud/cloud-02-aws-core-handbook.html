Step 02 · Beginner · Compute, storage, databases, networking, identity, and operations on AWS

AWS core services

AWS is the broadest cloud. This step covers the services you will use in most workloads and shows how they fit together, ending with the account-level habits that keep it safe and affordable.

2. Storage

  • S3: object storage with storage classes (Standard, Intelligent-Tiering, Glacier tiers), versioning, lifecycle rules, and Block Public Access on by default. S3 is the base of most data lakes.
  • EBS: block volumes for EC2. EFS and FSx: shared file systems.
  • Replicate and back up with S3 replication and AWS Backup; use Object Lock for immutability.

4. Networking

  • VPC with public and private subnets across at least two AZs; NAT gateways for egress, VPC endpoints (gateway and PrivateLink) to keep AWS traffic private.
  • Security groups are stateful and instance-level; NACLs are stateless and subnet-level.
  • Edge and traffic: Route 53, CloudFront, Application and Network Load Balancers, Global Accelerator, AWS WAF and Shield.
  • Connectivity: Transit Gateway, Direct Connect, Site-to-Site VPN.

5. Identity and security

  • Use IAM Identity Center for people and IAM roles for workloads; avoid IAM users with long-lived keys.
  • Policies: identity, resource, permission boundaries, and Service Control Policies at the organization level. Start least privilege and refine with IAM Access Analyzer.
  • KMS for keys, Secrets Manager and Parameter Store for secrets, GuardDuty, Security Hub and Inspector for detection, CloudTrail for audit.
