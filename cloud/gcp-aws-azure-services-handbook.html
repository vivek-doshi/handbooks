GCP ↔ AWS ↔ Azure
Service Equivalents

A working reference for engineers who think in GCP but need to speak AWS and Azure fluently — core platform services plus the full Vertex AI stack, mapped side by side with when-to-use guidance and the differences that actually matter.

01

How to Read This Handbook

// EVERY SERVICE, THREE CLOUDS, ONE VERDICT

Each entry below starts from a GCP service — the anchor most engineers using this handbook already think in — and maps it to the closest AWS and Azure equivalent. "Closest" rarely means identical. Where the products diverge meaningfully in architecture, consistency model, or operating cost, that's called out explicitly in a Key Difference block rather than papered over. Where GCP's own docs already recommend one option over another (e.g. Cloud Run over GKE by default), that guidance is preserved and carried into the AWS/Azure columns.

Google Cloud (anchor)
Amazon Web Services
Microsoft Azure
▸
Scope: This is an architecture decision aid, not a pricing calculator or a migration runbook. Service names, GA status, and product boundaries shift constantly across all three vendors — verify current SKUs and regional availability before committing to a design.
02

Compute & Containers

// GKE VS CLOUD RUN AND THEIR CROSS-CLOUD PEERS
GKE vs Cloud Run
Compute · Default = Serverless

Cloud Run is the default choice. Reach for GKE only when you need stateful workloads, complex networking (custom CNI, service mesh, multi-tenant network policy), GPU/TPU scheduling with fine-grained bin-packing, or you're already running a large fleet where the Kubernetes control plane pays for itself.

GCP
Cloud Run / GKE
Cloud Run: fully managed, scale-to-zero containers. GKE: managed Kubernetes control plane, Autopilot or Standard node pools.
AWS
App Runner / Fargate ↔ EKS
App Runner mirrors Cloud Run's simplicity but with a narrower feature set. Fargate-on-ECS is the more common serverless-container default in AWS shops. EKS mirrors GKE.
Azure
Container Apps ↔ AKS
Azure Container Apps is the closest Cloud Run analogue (built on KEDA + Dapr under the hood, scale-to-zero). AKS mirrors GKE.
✅
Default rule of thumb: stateless HTTP services, event-driven jobs, and APIs → Cloud Run / App Runner / Container Apps. Stateful workloads, GPU scheduling, service mesh, or custom networking → GKE / EKS / AKS.
⚠
Key difference: AWS has no single 1:1 Cloud Run product — App Runner is closest in developer experience but Fargate is more widely adopted in production AWS estates and has deeper ECS/EKS interoperability.
03

Networking & Content Delivery

// GLOBAL EDGE, ANYCAST, AND THE BACKBONE
Global Cloud Load Balancer (GCLB)
Networking · Anycast

A single anycast IP announced from every Google edge PoP simultaneously. Traffic enters the nearest PoP and travels the rest of the way to your backend over Google's private fiber backbone, not the public internet — this is GCLB's real advantage over regional load balancers.

GCP
Global External LB
Single anycast IP, L7 routing, integrates with Cloud Armor and Cloud CDN at the edge.
AWS
Global Accelerator + CloudFront/ALB
Global Accelerator gives anycast IPs and backbone routing; CloudFront is the CDN/edge layer. Two products stitched together where GCP ships one.
Azure
Front Door
Anycast entry, global L7 routing, WAF, and CDN in one product — closest single-SKU match to GCLB.
⚠
Key difference: AWS splits "get onto our backbone fast" (Global Accelerator) from "cache and serve at the edge" (CloudFront) into two billed services; GCP and Azure each bundle both concerns into one product.
04

API Gateway & Zero Trust Access

// GOVERNANCE AND IDENTITY BEFORE THE COMPUTE LAYER
Apigee
API Governance

Full-lifecycle API management: rate limiting, quota enforcement, monetization, and zero-trust policy checks applied before a request ever reaches the compute layer.

GCP
Apigee
Enterprise-grade API management platform; heavier than Cloud Endpoints, meant for external/partner-facing APIs at scale.
AWS
API Gateway (+ Verified Permissions)
Native API Gateway covers routing/throttling; Amazon Verified Permissions adds fine-grained authorization policy for zero-trust patterns.
Azure
API Management (APIM)
Closest feature-for-feature match to Apigee — policy XML pipelines, developer portal, monetization, and quota tiers.
✅
When to use: external/partner APIs needing monetization, versioning, and a developer portal → Apigee/APIM. Simple internal service routing → native API Gateway/Cloud Endpoints is enough and far cheaper.
Cloud IAP
Zero Trust · Identity

Verifies user identity at the edge and passes a signed OAuth assertion downstream — lets you expose internal apps without a VPN, enforcing zero trust before any request hits your VMs or containers.

GCP
Identity-Aware Proxy
Context-aware access, integrates with BeyondCorp Enterprise for device posture checks.
AWS
Verified Access
VPN-less zero-trust access to internal apps, evaluates identity + device trust signals per request.
Azure
Entra Private Access / App Proxy
Part of the Entra Suite's Security Service Edge; publishes internal apps through identity-verified tunnels.
05

Messaging & Eventing

// BROADCAST, POINT-TO-POINT, AND INFRA NOTIFICATIONS
Cloud Pub/Sub
One-to-Many Broadcast

Fully managed pub/sub messaging for one-to-many broadcast patterns — a single publish fans out to every subscribed consumer, each with its own delivery cursor.

GCP
Pub/Sub
Single service does both topic fan-out and ordered/keyed delivery.
AWS
SNS + SQS (custom fan-out)
No single equivalent — you wire SNS (topic/broadcast) to fan out into per-consumer SQS queues yourself. EventBridge is the closer analogue for routing-rule-based broadcast.
Azure
Service Bus Topics / Event Grid
Service Bus Topics give native topic/subscription fan-out closest to Pub/Sub; Event Grid is the routing-rule equivalent to EventBridge.
⚠
Key difference: Pub/Sub bundles broadcast + queueing in one product; AWS makes you compose SNS and SQS explicitly, which is more moving parts but more granular control per consumer.
Eventarc
Infra Notifications

Routes Google service notifications (infra-level events like "upload completed" in GCS, or Cloud Audit Log entries) to downstream handlers without you polling anything.

GCP
Eventarc
Standardized CloudEvents format across GCP service sources.
AWS
EventBridge (default bus)
Native AWS service events (S3, DynamoDB Streams, etc.) route through the default event bus with rule-based matching.
Azure
Event Grid
System topics emit built-in Azure resource events (Blob created, etc.) — direct structural match to Eventarc.
Cloud Tasks
Reliable One-to-One Delivery

Asynchronous one-to-one task execution with guaranteed at-least-once delivery, automatic retry with backoff, and rate-limited dispatch — the pattern to reach for when a downstream API is flaky or intentionally throttled.

GCP
Cloud Tasks
Push-based queue; you configure the HTTP target and dispatch rate directly.
AWS
SQS + Lambda (or SQS alone)
Pull-based by default — a consumer (often Lambda) polls the queue. Achieves the same at-least-once guarantee with a different delivery model.
Azure
Queue Storage / Service Bus Queues
Queue Storage for simple, cheap at-least-once queues; Service Bus Queues when you need sessions, dead-lettering, and duplicate detection.
⚠
Key difference: Cloud Tasks is push-based (it calls your endpoint on schedule); the AWS/Azure default pattern is pull-based (your worker polls the queue). Functionally equivalent, architecturally inverted.
06

Scheduling & Orchestration

// CRON JOBS AND STATEFUL WORKFLOW ENGINES
Cloud Scheduler
Cron

Fully managed cron job service — fires HTTP, Pub/Sub, or App Engine targets on a schedule with retry policy built in.

GCP
Cloud Scheduler
Standard unix-cron syntax, minimum 1-minute granularity.
AWS
EventBridge Scheduler
Purpose-built scheduler (replaced CloudWatch Events cron rules as the recommended path); supports one-off and recurring schedules at scale.
Azure
Logic Apps (Recurrence trigger) / Functions Timer Trigger
No single standalone "Scheduler" SKU — cron behavior is a trigger type on Logic Apps or Functions rather than its own product.
Cloud Workflows
Stateful Orchestration · Saga

Executes a sequence of services together as a stateful, step-by-step orchestration — supports long-running human-in-the-loop callbacks, retries, and saga-pattern compensation logic.

GCP
Workflows
YAML/JSON-defined steps, native connectors to GCP APIs, callback URLs for human-in-the-loop pauses.
AWS
Step Functions
The direct match — Amazon States Language, native saga/compensation patterns, `waitForTaskToken` for human-in-the-loop.
Azure
Logic Apps
Low-code visual designer, huge connector catalogue; Durable Functions is the code-first alternative for complex saga logic.
07

Streaming, ETL & IoT

// HIGH-THROUGHPUT AGGREGATION AND DEVICE INGESTION
Cloud Dataflow
Stream & Batch ETL

Unified batch and streaming data processing built on Apache Beam. Typically sits downstream of Pub/Sub, which acts as a shock absorber so bursty producers don't overwhelm the aggregation pipeline.

GCP
Dataflow
Apache Beam runner, autoscaling workers, unified batch + streaming API.
AWS
Managed Service for Apache Flink
Formerly Kinesis Data Analytics; the direct streaming-ETL analogue, typically paired with Kinesis Data Streams as the shock absorber.
Azure
Stream Analytics / Azure Data Factory
Stream Analytics for real-time SQL-like stream queries; Data Factory for batch ETL orchestration.
MQTT Broker (IoT)
Device Ingestion

A managed MQTT broker collects and routes telemetry from fleets of IoT devices into the cloud data plane.

GCP
Partner-managed MQTT (e.g. HiveMQ on GCP Marketplace)
Google retired Cloud IoT Core; the recommended path today is a Marketplace MQTT broker feeding Pub/Sub.
AWS
AWS IoT Core
Native managed MQTT broker with device shadows, rules engine, and fleet provisioning still fully supported.
Azure
Azure IoT Hub
Native managed MQTT/AMQP broker, device twins, and IoT Edge runtime for on-device compute.
⚠
Key difference: AWS and Azure both still ship a first-party managed IoT device broker; GCP's native Cloud IoT Core was deprecated, so the GCP path routes through a Marketplace partner broker into Pub/Sub instead.
08

Databases & Caching

// REGIONAL SQL, GLOBAL SPANNER, WIDE-COLUMN, AND WAREHOUSES
Memorystore
Redis Cache
GCP
Memorystore (Redis / Memcached)
AWS
ElastiCache (Redis / Valkey / Memcached)
Azure
Azure Cache for Redis

Near-identical positioning across all three — in-memory cache/session store in front of a primary database.

Cloud SQL
Regional Relational DB
GCP
Cloud SQL (MySQL/Postgres/SQL Server)
AWS
Amazon RDS
Azure
Azure SQL Database / DB for PostgreSQL

Standard managed regional relational database — single-region durability, read replicas, automated backups. Use this before reaching for a globally distributed option.

Cloud Spanner
Global · TrueTime · Multi-Region

Globally distributed, strongly consistent relational database using TrueTime for external consistency across regions. Reach for it only when you genuinely need multi-regional, globally consistent transactional writes.

GCP
Cloud Spanner
SQL interface with horizontal scale and global strong consistency — a genuinely distinct architecture.
AWS
Aurora Global Database / DynamoDB Global Tables
No true equivalent. Aurora Global Database gives multi-region reads with async replication (not strongly consistent globally); DynamoDB Global Tables gives multi-region NoSQL with eventual consistency.
Azure
Cosmos DB (Strong consistency mode)
Closest match — Cosmos DB can run in "Strong" consistency mode across regions, at a latency cost, approximating Spanner's guarantee.
⚠
Key difference: Spanner's TrueTime-based external consistency has no exact analogue on AWS or Azure — both require a deliberate trade-off (looser consistency for lower latency, or Cosmos DB's Strong mode for a rough match at higher write latency).
Bigtable
Wide-Column · Sub-ms Latency

Wide-column NoSQL store built for sub-millisecond latency at massive scale — the default choice for IoT telemetry and time-series streams needing hot-path reads/writes.

GCP
Bigtable
AWS
DynamoDB / Keyspaces (Cassandra-compatible)
Azure
Cosmos DB (Cassandra / Table API)
✅
When to use: IoT telemetry, time-series, ad-tech, or any hot-storage workload with predictable key access patterns and very high write throughput.
BigQuery
Cold Storage · Analytical Warehouse

Serverless data warehouse for large-scale historical/analytical queries — the cold-storage counterpart to Bigtable's hot path.

GCP
BigQuery
AWS
Amazon Redshift
Azure
Synapse Analytics (Dedicated/Serverless SQL Pool)
⚠
Key difference: BigQuery is serverless by default (pay-per-query or flat-rate slots, no cluster to size); Redshift historically required provisioned clusters, though Redshift Serverless has closed most of that gap.
Change Streams
Row-Level Triggers

Row-level change capture on Cloud Spanner or Cloud SQL — used to trigger downstream tasks whenever a row is inserted, updated, or deleted, without polling.

GCP
Spanner Change Streams / Cloud SQL + Datastream CDC
AWS
DynamoDB Streams / RDS via DMS CDC
Azure
Cosmos DB Change Feed

Object Storage Access Patterns

// SIGNED URLS FOR HEAVY, DIRECT UPLOADS
Signed URLs (GCS)
Payload-Heavy Uploads

Time-limited, credential-scoped URLs that let a client upload directly to object storage — for large video/photo payloads, this bypasses your application server entirely and avoids proxying gigabytes of traffic through compute you pay for.

GCP
GCS Signed URLs
AWS
S3 Presigned URLs
Azure
Blob Storage SAS Tokens
✅
When to use: any client-side upload of video, large images, or bulk payloads. Never proxy heavy binary payloads through your own compute layer if a signed/presigned URL can do it directly.

Encryption, Key Management & DLP

// CMEK, PII MASKING, AND PERIMETER PROTECTION
Cloud KMS
CMEK · Key Rotation

Manages customer-managed encryption keys (CMEK) so you — not the provider — control rotation policy, access, and destruction of the keys encrypting your data at rest.

GCP
Cloud KMS / Cloud HSM
AWS
AWS KMS / CloudHSM
Azure
Azure Key Vault (Managed HSM)
Cloud DLP API
PII Masking in Logs

Sensitive Data Protection scans and masks PII in logs and datasets — detecting patterns like SSNs, credit cards, and emails before they leak into downstream systems or analyst dashboards.

GCP
Sensitive Data Protection (DLP API)
AWS
Amazon Macie
Azure
Microsoft Purview / Azure AI Language PII Detection
⚠
Key difference: Macie is scoped specifically to S3 data classification; for masking PII inline in application logs (not just data-at-rest scanning), Azure's AI Language PII detection API is the closer functional match to DLP's inline redaction use case.
VPC Service Controls
Perimeter · Exfil Protection

A security perimeter around managed services that protects against accidental data exfiltration — even a correctly-authenticated identity can't move data across the perimeter boundary without explicit allowance.

GCP
VPC Service Controls
AWS
VPC Endpoints + SCPs (composed)
Azure
Private Link + Azure Policy
⚠
Key difference: GCP ships VPC-SC as one dedicated perimeter product. AWS and Azure achieve the equivalent posture by composing several primitives (VPC/Private endpoints + org-level policy guardrails) rather than a single named service.

Monitoring, Logging & SLIs

// P99 LATENCY AND ALERT THRESHOLDS
Cloud Monitoring & Logging
SLI/SLO · P99

Tracks Service Level Indicators — e.g. P99 latency for an AI inference endpoint — and fires alerts when a threshold is breached (a common pattern: trigger at 120ms P99 for a latency-sensitive path).

GCP
Cloud Monitoring + Cloud Logging
AWS
Amazon CloudWatch (Metrics + Logs + Alarms)
Azure
Azure Monitor (Metrics + Log Analytics)
✅
When to use: define SLOs against percentile latency (P95/P99), not averages — averages hide the tail latency that actually degrades user experience on AI/inference workloads.

Vertex AI Services

// THE FULL AI PLATFORM, SERVICE BY SERVICE

At the platform level, Vertex AI's closest peers are Amazon Bedrock (paired with SageMaker for the ML-ops layer) and Microsoft Foundry (formerly Azure AI Studio). All three converged on the same shape in 2025–2026: a foundation-model gateway, a managed agent runtime, and a full ML-ops stack sitting on top of the parent cloud's identity and governance plane. The individual service mappings below assume that platform-level context.

Vertex AI Agent Builder
Grounding · Search & Maps

Builds grounded agents with native Google Search and Maps grounding — reduces hallucination by tying model output to live, citable web and location data. Includes Agent Engine for managed runtime, sessions, and memory.

AWS
Bedrock AgentCore
Managed agent runtime with vault-backed identity/token management; strongest for zero-trust, multi-tenant agent deployments.
Azure
Azure AI Foundry Agent Service
Deepest integration with Microsoft 365 and Teams; the default pick for Microsoft-native enterprises.
GCP (this row)
Vertex AI Agent Builder / Agent Engine
Unique advantage: native Google Search/Maps grounding no competitor can replicate directly.
✅
When to use: pick Agent Builder when Search/Maps grounding or deep BigQuery-connected retrieval is core to the use case; pick AgentCore for AWS-native zero-trust multi-tenant needs; pick Foundry Agent Service for Microsoft 365/Teams-embedded agents.
Document AI
Multimodal Doc Parsing

Fully managed, multimodal document parsing — extracts structured fields from invoices, forms, and contracts without training a custom model per document type.

GCP
Document AI
AWS
Amazon Textract
Azure
Azure AI Document Intelligence
Vertex AI Vision Warehouse
Multimodal Vision · Media

Multimodal vision search and warehousing over video/image archives — built for media houses cataloguing and searching large video libraries by content, not just metadata.

GCP
Vertex AI Vision Warehouse
AWS
Rekognition Video + Kinesis Video Streams
Azure
Azure Video Indexer
Vertex AI Vector Search
Sub-ms Dense + Sparse Search

Approximate nearest-neighbor search over dense and sparse embeddings at sub-millisecond latency — the retrieval backbone for large-scale RAG and semantic search.

GCP
Vertex AI Vector Search
AWS
Amazon OpenSearch Service (k-NN) / S3 Vectors
Azure
Azure AI Search (vector mode)
Vertex AI Feature Store
Fully Managed Feature Store

Managed feature store with tight integration into Spanner and training pipelines — the system of record for numeric/tabular features feeding classic ML models like XGBoost, not just LLM workloads.

GCP
Vertex AI Feature Store
AWS
Amazon SageMaker Feature Store
Azure
Azure Machine Learning Feature Store
Vertex Multimodal Embeddings
Text / Image / Video → Vectors

Turns text, images, and video into a shared embedding space for cross-modal retrieval and similarity search.

GCP
Vertex AI Multimodal Embeddings API
AWS
Amazon Titan Multimodal Embeddings (via Bedrock)
Azure
Azure AI Vision multimodal embeddings
Vertex AI Model Monitoring
Drift Detection

Samples live inference traffic and triggers alerts when the input/output distribution statistically drifts away from the training baseline.

GCP
Vertex AI Model Monitoring
AWS
SageMaker Model Monitor
Azure
Azure ML Model Monitoring
Vertex AI Pipelines
Kubeflow · DAG Orchestration

Kubeflow-based DAG orchestrator for the clean → train → evaluate ML lifecycle — reproducible, versioned pipeline runs.

GCP
Vertex AI Pipelines
AWS
SageMaker Pipelines
Azure
Azure ML Pipelines
Vertex AI Model Registry
Canary Deployment Store

Central store for versioned models feeding canary and staged rollout deployments.

GCP
Vertex AI Model Registry
AWS
SageMaker Model Registry
Azure
Azure ML Model Registry
Vertex AI Search (Enterprise & Retail)
Managed RAG · Ecommerce

Fully managed RAG with third-party connectors for enterprise knowledge; a dedicated retail variant powers ecommerce search and product recommendations out of the box.

GCP
Vertex AI Search (enterprise + retail)
AWS
Amazon Kendra (enterprise) + Amazon Personalize (retail)
Azure
Azure AI Search + Azure Personalizer
⚠
Key difference: GCP bundles enterprise RAG and retail search/recs under one product family; AWS and Azure split them into separate services (search vs. recommendation engine) that you compose yourself.
Media APIs
Translate · Timestamping · Synthesis

Off-the-shelf translation, word-level timestamping, and audio synthesis — no custom model training required for common media-localization tasks.

GCP
Media Translation / Speech-to-Text / Text-to-Speech APIs
AWS
Amazon Translate / Transcribe / Polly
Azure
Azure AI Speech + Azure AI Translator
ℹ
Platform-level naming keeps shifting. Azure AI Studio was rebranded Microsoft Foundry in late 2025; Google increasingly routes model/runtime docs through a "Gemini Enterprise Agent Platform" framing even though the product is still experienced as Vertex AI day to day. Verify current naming before writing it into architecture diagrams that will outlive this handbook.
