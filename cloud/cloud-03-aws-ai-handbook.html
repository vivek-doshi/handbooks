Step 03 · Intermediate · Bedrock, SageMaker, AI accelerators, and responsible AI on AWS

AWS AI and machine learning

AWS offers a managed foundation-model platform, a full ML platform, and its own AI silicon. This step shows which to choose and how to secure and govern each.

2. Amazon Bedrock

  • One API for many models; use the Converse API for a consistent interface and tool calling. Model availability varies by region, and cross-region inference profiles help throughput.
  • Customization: prompt engineering first, then retrieval, then fine-tuning or distillation if needed.
  • Throughput: on-demand, batch (cheaper, asynchronous), and provisioned throughput for steady load. Prompt caching reduces cost and latency for repeated context.
  • Evaluation: use model and RAG evaluation features and your own test sets before choosing a model.

3. Retrieval-augmented generation

RAG grounds answers in your data. On AWS, Bedrock Knowledge Bases manage ingestion (chunking, embeddings), a vector store (OpenSearch Serverless, S3 Vectors, Aurora PostgreSQL with pgvector and others), retrieval and citations. Build your own pipeline when you need custom chunking, hybrid search, reranking or strict control.

  1. Ingest documents from S3 and other sources.
  2. Chunk and embed; store vectors with metadata for access filtering.
  3. Retrieve, optionally rerank, and generate with citations.
  4. Evaluate groundedness and relevance continuously.

4. Agents and tools

Bedrock Agents and Amazon Bedrock AgentCore support tool-using agents. AgentCore provides managed runtime, memory, identity, gateway for tools, and observability for agents built with any framework (for example Strands Agents, LangGraph). Use open protocols such as MCP for tool access, give agents narrowly scoped identities, and require human approval for high-impact actions.

5. SageMaker AI

  • Studio for notebooks and IDEs; Pipelines for repeatable workflows; Model Registry for versioning and approvals.
  • Training: managed jobs, spot training for savings, distributed training; HyperPod for resilient large clusters.
  • Inference: real-time, serverless, asynchronous, batch; multi-model and inference-component endpoints to raise utilisation.
  • JumpStart offers open-weight models to deploy or fine-tune in your account.
  • Monitoring: Model Monitor for drift and quality; Clarify for bias and explainability.

Compare cost per token or per training step on your workload, not list price alone, and plan for capacity reservations for scarce GPUs.

7. Security, guardrails and cost

  • Guardrails for Bedrock: content filters, denied topics, sensitive-information redaction, prompt-attack filters, and contextual grounding checks.
  • Private connectivity with PrivateLink; KMS keys; IAM least privilege per model and per knowledge base; CloudTrail and model-invocation logging for audit.
  • AWS states that Bedrock does not use your prompts or outputs to train base models; still classify data and verify terms for your regulatory needs.
  • Cost controls: choose the smallest model that passes evaluation, cache prompts, batch where latency allows, cap tokens, and tag by application.
