Step 07 · Intermediate · Practice safely on your laptop and master Docker and kubectl operations

Local Kubernetes and the daily CLI

A local cluster lets you apply Steps 05 and 06 with zero cloud cost, and a disciplined command routine turns that practice into fast, safe operations. This step covers both.

1. Choosing a local cluster

ToolStrength
minikubeRich add-ons, profiles, multiple drivers, good for learning
kindClusters in Docker; ideal for CI and multi-node tests

2. minikube essentials

  • minikube start --driver=docker --cpus=4 --memory=8g then kubectl get nodes.
  • Add-ons enable ingress, metrics-server, dashboard, and registry with one command (minikube addons enable ingress).
  • Profiles (-p name) give isolated clusters, for example one per Kubernetes version.
  • Reach services with minikube service, minikube tunnel (LoadBalancer), or kubectl port-forward.
  • Use images without a registry: minikube image load app:dev or build directly with minikube image build.
PitfallLocal clusters are not production. Resource limits, storage, networking and cloud integrations differ; use them to validate manifests and flows, not capacity.

3. Contexts, namespaces, and safety

  • Always know your context: kubectl config current-context; use a prompt indicator or kubectx/kubens.
  • Set a default namespace per context to avoid accidental cross-namespace changes.
  • Use --dry-run=server and kubectl diff before applying.
  • Prefer read-only kubeconfigs for production browsing.

5. kubectl routine for daily operations

GoalCommand
Overviewkubectl get all -n ns, kubectl top pods
Why is it failing?kubectl describe, kubectl get events --sort-by=.lastTimestamp
Logs, multi-podkubectl logs -l app=x --all-containers -f (or stern)
Scale and roll outkubectl scale, kubectl rollout status|undo
Debugkubectl debug -it pod --image=busybox --target=app
Accesskubectl port-forward svc/x 8080:80
Node workkubectl cordon|drain|uncordon

Cleanup of stuck or failed objects: delete failed pods with kubectl delete pod --field-selector=status.phase==Failed -A; for stuck Terminating pods find the finalizer first rather than force-deleting blindly.

PracticeStart a kind or minikube cluster, deploy an app, load a locally built image, expose it, break the readiness probe, and use only the commands above to find and fix it.
