gRPC and Protocol Buffers

gRPC delivers strongly typed, code-generated remote procedure calls over HTTP/2. Paired with Protocol Buffers for compact binary serialization, it provides high-performance, low-latency inter-service communication for microservice architectures.

2. Protocol Buffers Deep Dive

Protobuf serializes messages into a binary format where fields are identified strictly by integer tag numbers (1 to \(2^{29}-1\)), never by field names. Tags 1–15 take only 1 byte to encode on the wire; reserve them for high-frequency fields.

Advanced Protobuf Definition

syntax = "proto3";

package commerce.v1;

import "google/protobuf/timestamp.proto";

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0; // Protobuf enum 0 must always be UNSPECIFIED
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
  ORDER_STATUS_FAILED = 3;
}

message OrderItem {
  string sku = 1;
  int32 quantity = 2;
  int64 price_cents = 3;
}

message CreateOrderRequest {
  string customer_id = 1;
  repeated OrderItem items = 2;
  
  // Polymorphic payment selection
  oneof payment_method {
    string credit_card_token = 3;
    string crypto_wallet_address = 4;
    string bank_account_id = 5;
  }

  map<string, string> metadata = 6;
  google.protobuf.Timestamp client_timestamp = 7;
}

message OrderResponse {
  string order_id = 1;
  OrderStatus status = 2;
  google.protobuf.Timestamp created_at = 3;
}

service OrderService {
  rpc CreateOrder(CreateOrderRequest) returns (OrderResponse);
  rpc WatchOrderStatus(OrderResponse) returns (stream OrderResponse); // Server stream
}

Rules for Safe Schema Evolution

  1. Never change an existing field's tag number. Doing so completely corrupts binary deserialization.
  2. Never reuse deleted field numbers. Mark removed fields as reserved: 
    message OrderItem {
  reserved 4, 8 to 12;
  reserved "tax_amount", "discount_code";
}
  3. New fields must be optional. Old clients reading new payloads will simply skip unknown tags without crashing.

3. Modern Tooling: The Buf Ecosystem

Rather than managing messy native protoc installations with scattered plugins, modern teams adopt Buf:

  • Buf Lint: Enforces universal style guides (camelCase field names, package naming, enum zero-value checks).
  • Buf Breaking Change Detection: Runs in CI against git main branch to prevent any PR from merging backward-incompatible schema changes.
  • Buf Schema Registry (BSR): A centralized repository that generates and publishes client libraries (npm, Maven, Go modules) automatically upon commit.

HTTP/2 Multiplexing and Flow Control

In HTTP/1.1, each concurrent request requires a separate physical TCP connection (head-of-line blocking). HTTP/2 multiplexes hundreds of independent bidirectional RPC streams over a single long-lived TCP connection using binary frames (HEADERS, DATA, RST_STREAM). This eliminates repeated TCP handshakes and TLS renegotiation latency.

5. Load Balancing: Why L4 Load Balancers Fail with gRPC

Because gRPC opens a single persistent HTTP/2 TCP connection, traditional Layer-4 load balancers (AWS NLB, standard IP round-robin) route all subsequent RPC requests across that connection to the exact same backend pod. One backend server gets overwhelmed while others sit at 0% CPU.

Solutions for gRPC Load Balancing

  • L7 Proxy Load Balancing (Recommended): Use an HTTP/2-aware proxy (Envoy, Traefik, Nginx). The proxy terminates the HTTP/2 connection and load-balances individual RPC requests across backend instances.
  • Client-Side Load Balancing: The gRPC client stub resolves backend IP addresses directly from DNS or Kubernetes endpoints and balances RPCs locally across instances using round_robin.
  • Service Mesh (Istio / Linkerd): Envoy sidecars intercept all inter-pod gRPC traffic and provide transparent L7 load balancing, mTLS, and distributed telemetry.

6. Production Resilience: Deadlines and Cancellation

In distributed systems, a caller must always specify a deadline. In gRPC, deadlines propagate across downstream hops:

// Client sets a strict 500ms deadline
Context ctx = Context.current().withDeadlineAfter(500, TimeUnit.MILLISECONDS);
orderService.createOrder(ctx, request);

// On server: If client cancels or deadline expires, abort expensive work!
if (Context.current().isCancelled()) {
  logger.warn("Client canceled RPC, aborting database query");
  return;
}

7. Practical Exercises

  1. Protobuf Schema Design: Write a production-ready .proto contract for a ride-hailing dispatch service. Define a unary RequestRide RPC and a server-streaming StreamDriverLocations RPC. Use enums with explicit 0-value defaults and field timestamps.
  2. Backward Compatibility Validation: Given a proto message with fields 1, 2, and 3: Can you safely rename field 2 from user_name to full_name? Can you change field 3 from int32 to int64? Justify your answers using binary wire encoding rules.
  3. Envoy gRPC Configuration: Sketch the Envoy proxy configuration needed to accept gRPC-Web from a browser client and forward it to a backend gRPC service on port 50051.
