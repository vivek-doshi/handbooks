Step 01 · Beginner · Prerequisite for design work

Computer science foundations for architects

Architecture decisions become clearer when you can estimate the cost of the work a system performs. This lesson builds practical intuition for data structures, algorithms, memory, and the common problem-solving patterns behind production software.

Big-OData structuresProblem patternsPractice: choose a data model

What you will be able to do

  • Compare algorithm costs as data grows without relying on one benchmark.
  • Select arrays, lists, queues, maps, trees, heaps, or graphs to fit access patterns.
  • Recognize sorting, searching, recursion, and dynamic-programming problems.
  • Explain how memory layout and data movement affect real systems.
Why this belongs in an architecture pathCapacity estimates, cache design, search indexes, queues, and graph traversals all depend on the same core tradeoffs.

1. Complexity and the memory model

Big-O describes how resource use grows with input size, not an exact runtime. For an input of n items, common growth rates are:

ClassExampleGrowth intuition
O(1)Array index lookupOne bounded operation
O(log n)Binary search in sorted dataEach step removes a fraction
O(n)Scan every recordWork grows with record count
O(n log n)Comparison sortingDivide, then combine
O(n²)Compare every pairDoubling input may quadruple work

Consider time and space separately. Also consider constants, cache locality, allocation, contention, I/O, and network calls: asymptotic complexity is a model, not a substitute for measuring a real workload.

Memory and representation

Arrays store items contiguously and are cache-friendly; linked nodes require pointer chasing and extra allocation. A hash table buys average constant-time lookup with extra memory and occasional resize cost. At a service boundary, serialization and copies can cost more than the in-process algorithm.

2. Core data structures

StructureUse it forTradeoff to remember

Example: choose the structureA job dispatcher that repeatedly selects the earliest deadline fits a min-heap. A deduplication pass needs a set. A dependency planner needs a directed graph and a cycle check.

3. Sorting, searching, recursion, and problem patterns

Searching and sorting

Linear search works on unsorted input in O(n). Binary search needs a sorted or monotonic search space and runs in O(log n). Sorting is not automatically beneficial: include its one-time cost and the number of later queries it enables.

Recursion

Recursive solutions reduce a problem to smaller instances. Confirm a terminating base case, progress toward it, and acceptable call-stack depth. For deep or untrusted input, use an explicit stack or iterative approach.

Reusable problem patterns

  • Two pointers / sliding window: contiguous ranges and pairwise scans.
  • Hashing: fast membership, counts, and complements.
  • Breadth-first / depth-first search: reachability, shortest unweighted paths, and component discovery.
  • Binary search on answer: find a boundary in a monotonic predicate.
  • Dynamic programming: overlapping subproblems and optimal substructure; define state, transition, base case, and evaluation order.

4. A repeatable way to solve a problem

  1. Clarify input size, ordering, duplicates, limits, and required output.
  2. Write a simple correct approach before optimizing it.
  3. State the invariant or subproblem that makes the approach correct.
  4. Estimate time and space complexity, including auxiliary structures.
  5. Test empty, single-item, duplicate, boundary, and large inputs.
  6. Benchmark representative data when the decision matters in production.
PracticeFor a service that stores user IDs and checks membership millions of times, compare scanning a list with a hash set. Then explain how memory overhead, ordering, persistence, and distributed deployment change the answer.

Choosing the right structure

Start from required operations, not a favorite structure. Write a small operation table (lookup, insert, delete, ordered iteration, range query), estimate frequency and scale, then choose the simplest structure that meets measured latency and memory goals.
