# Documentation Rules

Documentation standards for `README.md`, handbook pages, and repo support files.

## Writing Principles

- Prefer clear, direct language over long explanations.
- Explain what the handbook is for, where the reader should go next, and what changed.
- Keep examples realistic and aligned with the current repository structure.
- Use the same terms across README, handbook pages, and `.ai` context.

## Structure Standards

- Start with purpose and scope.
- Put the most useful summary near the top.
- Include validation or confirmation where a page change needs it.
- For handbook pages, mention companion links or source references near the top when relevant.

## Repository Expectations

- If a handbook card changes, update `index.html`, `README.md`, and the `.ai` context together.
- Keep external links current and purposeful.
- Make sure new handbook entries match the existing folder/topic structure.
- When a page depends on shared UI, document that dependency in the repo guidance.

## Quality Bar

- No stale handbook references.
- No ambiguous guidance about where a page lives.
- No outdated counts or index references.
- No instruction files that drift away from the actual repo.
