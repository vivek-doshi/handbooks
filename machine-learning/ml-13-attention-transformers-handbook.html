Attention and transformers

The transformer is the architecture behind modern language, vision and multimodal AI. This final step explains attention, builds the core block in code, compares the model families, and shows how to use pretrained models, then points to the generative AI handbooks for what comes next.

1. Why attention

RNNs squeeze a whole sequence into one hidden state and read it one step at a time. Attention lets every position look directly at every other position and decide how much each one matters. That removes the memory bottleneck and allows the whole sequence to be processed in parallel on GPUs.

Self-attention in three ideas

  • Each token is turned into three vectors: a query (what am I looking for), a key (what do I offer) and a value (what I contribute).
  • Scores are the dot product of a query with every key, scaled by the square root of the key size and passed through softmax to become weights that sum to 1.
  • The output is the weighted sum of the values: softmax(Q K^T / sqrt(d)) V.
import math, torch, torch.nn as nn, torch.nn.functional as F

def attention(q, k, v, mask=None):
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))
    return F.softmax(scores, dim=-1) @ v

class SelfAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.h, self.dk = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.out = nn.Linear(d_model, d_model)

    def forward(self, x, causal=False):
        B, T, D = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q, k, v = (t.view(B, T, self.h, self.dk).transpose(1, 2) for t in (q, k, v))
        y = F.scaled_dot_product_attention(q, k, v, is_causal=causal)   # fused, fast kernel
        return self.out(y.transpose(1, 2).reshape(B, T, D))
  • Multi-head attention runs several attention computations in parallel so each head can specialise (syntax, position, reference).
  • Causal masking stops a token from seeing later tokens; it is what makes a model generate text one token at a time.
  • Cost: attention compares every token with every other, so compute and memory grow with the square of the sequence length. Efficient kernels and sparse or sliding-window variants reduce this.

2. The transformer block

  1. Embeddings and positions: tokens become vectors; position information is added (sinusoidal or learned in early models, rotary embeddings in many current ones) because attention alone ignores order.
  2. Self-attention mixes information across tokens.
  3. Feed-forward network: a small MLP applied to each token; it holds much of the model's knowledge.
  4. Residual connections and layer normalisation around each sub-layer keep deep stacks trainable (step 10).
  5. Repeat for dozens of layers, then add an output head.
class Block(nn.Module):
    def __init__(self, d_model=256, n_heads=8, d_ff=1024, p=0.1):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.attn = SelfAttention(d_model, n_heads)
        self.ff = nn.Sequential(nn.Linear(d_model, d_ff), nn.GELU(), nn.Linear(d_ff, d_model))
        self.drop = nn.Dropout(p)

    def forward(self, x, causal=False):
        x = x + self.drop(self.attn(self.ln1(x), causal))     # pre-norm residual
        return x + self.drop(self.ff(self.ln2(x)))

3. The three model families

FamilyAttentionExamplesBest for
Encoder-onlyBidirectional (sees the whole input)BERT, RoBERTa, DeBERTa, sentence embedding modelsClassification, search embeddings, extraction, ranking
Decoder-onlyCausal (sees only the past)GPT-style and open-weight chat and code modelsText generation, chat, code, reasoning, agents
Encoder-decoderEncoder reads the input; decoder generates with cross-attentionT5, BART, Whisper (speech)Translation, summarisation, speech to text
Vision transformers (ViT)Patches of an image as tokensViT, CLIP, SigLIPImage classification, image-text matching, multimodal models

Today's large language models are overwhelmingly decoder-only, pretrained to predict the next token on huge text and code corpora, then instruction-tuned and aligned with human or AI preference data. Multimodal models add image, audio and video tokens to the same sequence.

4. Tokens, embeddings and context

  • Tokenisation: text is split into sub-word tokens (byte-pair encoding or similar), roughly 3 to 4 characters of English each. Costs, limits and speed are measured in tokens, and tokenisers differ between models.
  • Embeddings: each token id maps to a learned vector; models also output embeddings you can use for search and classification.
  • Context window: the maximum number of tokens a model can attend to. Longer is not always better; models can miss details in the middle of very long inputs.
  • KV cache: during generation, keys and values of past tokens are cached so each new token is cheap; it is also the main memory cost of serving.
  • Sampling: temperature, top-p and top-k control how random the next-token choice is.

5. Dense versus mixture-of-experts

DenseMixture of experts (MoE)
IdeaEvery parameter is used for every tokenA router sends each token to a few expert sub-networks
Compute per tokenProportional to total parametersOnly the active experts, so much lower than total size
MemoryTotal parametersStill all experts must be loaded
ProsSimpler, easier to fine-tune and serveMore capacity for the same compute
ConsCostly to scaleHarder to train, balance and serve; memory-heavy

Many recent frontier and open-weight models are MoE. When comparing models, look at both total and active parameters.

6. Using pretrained transformers

from transformers import pipeline
from sentence_transformers import SentenceTransformer, util

clf = pipeline("sentiment-analysis", model="distilbert/distilbert-base-uncased-finetuned-sst-2-english")
print(clf("The onboarding was smooth and support was fast."))

enc = SentenceTransformer("all-MiniLM-L6-v2")                     # small embedding model
a, b = enc.encode(["reset my password", "I forgot my login"])
print(util.cos_sim(a, b))                                         # semantic similarity
NeedApproach
Classify or extract from textFine-tune an encoder, or use embeddings plus logistic regression
Search by meaningEmbedding model plus a vector index
Generate, summarise, converseInstruction-tuned decoder model through an API or a local runtime
Domain behaviour or stylePrompting and retrieval first; fine-tune (LoRA) only if needed

Know the limitsLanguage models can state wrong things fluently (hallucination), reflect biases in their data, and be manipulated through their inputs. Evaluate on your own tasks, ground answers in retrieved sources, and add human review where errors are costly.
