Decision trees, random forests and boosting

On structured, tabular data, tree ensembles are usually the strongest practical choice. This step builds from one tree to random forests and gradient boosting, and shows how to tune them without overfitting.

Decision treesRandom forestBoostingXGBoost, LightGBM, CatBoostStackingChooser

1. Decision trees

Decision tree

  • What it does: Learns a flowchart of if-then questions on features that ends in a prediction at each leaf.
  • How it works: At each node it picks the feature and threshold that best separate the targets, measured by Gini impurity or entropy (classification) or variance reduction (regression), then repeats on each side until a stopping rule is met.
  • Use it when: You need a model a non-expert can read, mixed numeric and categorical data, non-linear patterns with minimal preparation (no scaling needed), or as the building block of ensembles.
  • Avoid it when: You want top accuracy on its own (a single tree is unstable and overfits), or smooth predictions (trees predict in steps and cannot extrapolate beyond the training range).
  • Key settings: max_depth, min_samples_leaf, min_samples_split, max_leaf_nodes, and ccp_alpha (cost-complexity pruning). Unrestricted trees memorise the training data.
from sklearn.tree import DecisionTreeClassifier, plot_tree, export_text

tree = DecisionTreeClassifier(max_depth=4, min_samples_leaf=20, random_state=0).fit(X_train, y_train)
print(export_text(tree, feature_names=list(X_train.columns)))     # human-readable rules
Why single trees overfitA tree grown to full depth gets 100% training accuracy by isolating every row. Small changes in the data produce a very different tree (high variance). Ensembles fix this by averaging many trees.

2. Bagging and random forests

Random forest

  • What it does: Trains many decision trees on different random samples and features, then averages (regression) or votes (classification).
  • How it works: Bagging: each tree sees a bootstrap sample of the rows. Feature randomness: each split considers only a random subset of features. Averaging many different, decorrelated trees cuts variance without raising bias much.
  • Use it when: A strong, low-tuning default on tabular data; noisy data; mixed feature types; you want out-of-bag error and feature importances for free.
  • Avoid it when: You need the last bit of accuracy (boosting usually wins), very fast low-latency prediction on tiny hardware, or extrapolation beyond the training range.
  • Key settings: n_estimators (more is better until it plateaus; 200 to 500), max_features (sqrt for classification), max_depth, min_samples_leaf, class_weight, n_jobs=-1.
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(n_estimators=300, min_samples_leaf=3, n_jobs=-1,
                            oob_score=True, class_weight="balanced_subsample", random_state=0)
rf.fit(X_train, y_train)
print("out-of-bag score:", rf.oob_score_)
  • Out-of-bag (OOB) score: each tree is tested on the rows it did not see, giving a free validation estimate.
  • Feature importance caveat: built-in impurity importance favours high-cardinality features. Prefer permutation importance or SHAP (step 08).
  • Extra Trees (ExtraTreesClassifier) pick split thresholds at random: faster and sometimes more accurate.

3. Boosting

Where bagging averages independent trees, boosting builds trees sequentially, each one correcting the mistakes of the ones before. It reduces bias and typically reaches the highest accuracy on tabular data.

MethodIdea
AdaBoostRe-weights rows so later learners focus on previously misclassified ones
Gradient boostingEach new small tree fits the gradient of the loss (the residual errors) of the current ensemble
Histogram-based gradient boostingBins feature values into histograms for much faster training; the modern basis of scikit-learn's HistGradientBoosting*, LightGBM and XGBoost

The three parameters that matter most

  • learning_rate (shrinkage): small values (0.03 to 0.1) generalise better but need more trees.
  • n_estimators (number of trees): set high and use early stopping on a validation set to pick the best count automatically.
  • Tree complexity (max_depth 3 to 8 or num_leaves): shallow trees are safer.

Also tune subsample and colsample_bytree (0.6 to 1.0), min_child_weight or min_data_in_leaf, and L1/L2 regularisation. Boosting overfits noisy labels more readily than random forests, so validate carefully.

4. XGBoost, LightGBM, CatBoost and scikit-learn

LibraryStrengthsNotes
HistGradientBoosting* (scikit-learn)No extra dependency, native missing values and categoricals, early stoppingGreat first boosting model
XGBoostMature, accurate, GPU support, wide ecosystemStrong default; many deployment options
LightGBMVery fast on large data, leaf-wise growth, native categoricalsWatch overfitting on small data; tune num_leaves
CatBoostBest-in-class native handling of categorical features, robust defaultsSlower to train; excellent with little tuning
import lightgbm as lgb
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.metrics import roc_auc_score

# scikit-learn: nothing extra to install
hgb = HistGradientBoostingClassifier(learning_rate=0.06, max_iter=1000,
        early_stopping=True, validation_fraction=0.15, n_iter_no_change=30, random_state=0)
hgb.fit(X_train, y_train)

# LightGBM with an explicit validation set and early stopping
model = lgb.LGBMClassifier(n_estimators=5000, learning_rate=0.03, num_leaves=31,
                           subsample=0.8, subsample_freq=1, colsample_bytree=0.8)
model.fit(X_train, y_train, eval_set=[(X_val, y_val)],
          callbacks=[lgb.early_stopping(100), lgb.log_evaluation(0)])
print(roc_auc_score(y_test, model.predict_proba(X_test)[:, 1]))

XGBoost (xgboost.XGBClassifier) and CatBoost (catboost.CatBoostClassifier) follow the same fit and predict pattern, so you can swap them in and compare on identical cross-validation folds.

5. Voting and stacking

  • Voting: average the predictions of different model types (VotingClassifier). Simple, and helps when models make different errors.
  • Stacking: train a final model on the out-of-fold predictions of base models (StackingClassifier). Can add a small gain, at the cost of complexity and training time.
  • Rule of thumb: tune one good boosting model first; ensemble only if you need the extra fraction of a percent and can afford to maintain it.
from sklearn.ensemble import StackingClassifier, RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression

stack = StackingClassifier(
    estimators=[("rf", RandomForestClassifier(300, n_jobs=-1)),
                ("hgb", HistGradientBoostingClassifier())],
    final_estimator=LogisticRegression(max_iter=1000), cv=5)

6. Which tree model should I use?

NeedChoose
Explain a decision step by stepShallow decision tree
Solid result with almost no tuningRandom forest
Best accuracy on tabular dataGradient boosting: HistGradientBoosting, LightGBM, XGBoost or CatBoost
Many high-cardinality categorical columnsCatBoost or LightGBM with native categoricals
Millions of rows, speed criticalLightGBM or XGBoost (histogram, GPU)
Very small dataset (hundreds of rows)Regularised linear model or a small forest; consider tabular foundation models such as TabPFN as an emerging option
Extrapolating a trend beyond the training rangeLinear model or a model of the trend plus a tree on the residuals
Reality check on tabular dataGradient-boosted trees remain the strongest general default for structured data, and deep learning rarely beats them without large data or heavy tuning (step 10). Reach for a neural network when your inputs are images, text, audio or sequences.
Practice
  1. Fit a decision tree with depths 1, 3, 6, 12 and unlimited; plot train vs validation score to see overfitting appear.
  2. Compare random forest, HistGradientBoostingClassifier and LightGBM with the same 5-fold cross-validation.
  3. Rank features by impurity importance and by permutation importance. Do they agree?
