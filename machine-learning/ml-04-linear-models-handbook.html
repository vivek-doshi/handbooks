Step 04 · Beginner · Predicting numbers and probabilities with the simplest, most interpretable models

Linear and logistic regression

Linear models are the best first algorithm for most tabular problems: fast, interpretable, and a strong baseline. Understanding them also unlocks regularisation, loss functions and gradient descent, which every later model reuses.

Linear regressionRegularisationGradient descentLogistic regressionLoss functionsWhen to use

1. Linear regression

Predicts a number as a weighted sum of features: y = w1*x1 + w2*x2 + ... + b. Training finds the weights that minimise the sum of squared errors (ordinary least squares).

Linear regression (OLS)

  • What it does: Fits a straight line (or plane) through the data to predict a continuous value.
  • How it works: Chooses weights that minimise mean squared error. It has a closed-form solution, so training is instant and deterministic.
  • Use it when: The relationship is roughly linear, you need to explain the effect of each feature ("each extra bedroom adds about X"), or you need a fast baseline.
  • Avoid it when: Relationships are strongly non-linear, features are highly correlated with each other (unstable weights), or outliers dominate.
  • Key settings: Almost none. Use regularised variants (below) to control complexity.
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, r2_score

m = LinearRegression().fit(X_train, y_train)
pred = m.predict(X_test)
print(mean_absolute_error(y_test, pred), r2_score(y_test, pred))
print(dict(zip(X_train.columns, m.coef_)))    # interpretable weights

Assumptions worth checking

  • Linearity: plot residuals against predictions; a curve means missing non-linearity.
  • Constant spread of errors: a funnel shape means errors grow with the target; try modelling the log of the target.
  • No strong multicollinearity: if two features are near copies of each other, their weights become unstable. Drop one or use ridge.
  • Independent errors: time series and grouped data violate this; use appropriate splits.

Polynomial and interaction features

To capture curves with a linear model, add powers and products of features, then scale. Higher degrees overfit quickly, so keep them small and regularise.

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import Ridge

model = make_pipeline(PolynomialFeatures(degree=2, include_bias=False),
                      StandardScaler(), Ridge(alpha=1.0))

2. Regularisation: ridge, lasso and elastic net

Regularisation adds a penalty on large weights to the loss. It trades a little bias for much lower variance, which fights overfitting, especially with many features or few rows. Always scale features first.

MethodPenaltyEffectUse when
Ridge (L2)Sum of squared weightsShrinks all weights, keeps all featuresMany correlated features; default choice
Lasso (L1)Sum of absolute weightsDrives some weights exactly to zero (feature selection)You suspect many features are irrelevant
Elastic netMix of L1 and L2Selection plus stability with correlated groupsLasso is unstable on correlated features
from sklearn.linear_model import RidgeCV, LassoCV, ElasticNetCV
ridge = RidgeCV(alphas=[0.01, 0.1, 1, 10, 100]).fit(X_train_scaled, y_train)
lasso = LassoCV(cv=5).fit(X_train_scaled, y_train)
print(ridge.alpha_, (lasso.coef_ != 0).sum(), "features kept by lasso")

The strength is alpha in scikit-learn (larger means more shrinkage); choose it by cross-validation. For classifiers the equivalent knob is C, the inverse strength.

3. Gradient descent and loss functions

OLS has a formula, but most other models are trained with gradient descent: repeatedly compute the gradient of the loss and step the weights downhill (step 02).

VariantUses per stepTrade-off
BatchAll rowsStable, slow on big data
Stochastic (SGD)One rowFast, noisy
Mini-batchA small batch (32 to 1024)The practical default, used by deep learning
import numpy as np
rng = np.random.default_rng(0)
X = rng.normal(size=(200, 1)); y = 3 * X[:, 0] + 2 + rng.normal(0, .3, 200)

w, b, lr = 0.0, 0.0, 0.1
for _ in range(200):
    err = (w * X[:, 0] + b) - y
    w -= lr * 2 * (err * X[:, 0]).mean()
    b -= lr * 2 * err.mean()
print(w, b)       # approx 3 and 2

4. Logistic regression (classification)

Despite the name, logistic regression is a classifier. It computes the same weighted sum as linear regression, then squeezes it through the sigmoid function to get a probability between 0 and 1. Predict the positive class when the probability passes a threshold (0.5 by default, but tune it for your costs).

Logistic regression

  • What it does: Estimates the probability that a row belongs to a class.
  • How it works: Minimises log loss (cross-entropy) with gradient-based solvers. For more than two classes it uses softmax, which gives one probability per class.
  • Use it when: You need a strong, fast, interpretable baseline, calibrated probabilities, or a model that regulators can audit. Works well with many sparse features such as text TF-IDF.
  • Avoid it when: The decision boundary is clearly non-linear and you cannot engineer features to fix that; use trees or boosting instead.
  • Key settings: C (inverse regularisation, default 1.0), penalty (l1, l2, elasticnet), class_weight="balanced" for imbalance, solver.
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import classification_report

clf = make_pipeline(StandardScaler(), LogisticRegression(C=1.0, class_weight="balanced", max_iter=1000))
clf.fit(X_train, y_train)
print(classification_report(y_test, clf.predict(X_test)))
proba = clf.predict_proba(X_test)[:, 1]          # probabilities, not just labels
  • Reading coefficients: exp(weight) is the odds ratio, the multiplier on the odds of the positive class for one unit (or one standard deviation, if scaled) increase in the feature.
  • Probabilities: logistic regression is usually well calibrated; many other models are not (step 08).
  • Multiclass: scikit-learn fits a softmax model automatically when there are more than two classes; no extra setting is needed.

5. Beyond the basics

  • Generalised linear models: Poisson regression for counts, Gamma regression for positive skewed values such as claim amounts (PoissonRegressor, GammaRegressor).
  • Robust regression: HuberRegressor and RANSACRegressor when outliers are present.
  • Generalised additive models (GAMs): linear-style interpretability with curved per-feature effects; useful for regulated settings.
  • Stochastic solvers: SGDRegressor and SGDClassifier scale linear models to very large datasets and support partial_fit for streaming.

6. When to use linear models

SituationChoice
First model on any tabular problemLinear or logistic regression as the baseline
Interpretability or audit is requiredLinear, logistic, or a GAM
Many features, few rowsRidge, lasso or elastic net
Sparse high-dimensional data (text)Logistic regression or linear SVM with TF-IDF
Complex interactions and non-linearityMove to trees and boosting (step 06)
Practice
  1. Fit a linear regression on a housing dataset, then plot residuals against predictions. Is there a pattern?
  2. Compare OLS, ridge and lasso using cross-validated MAE. How many features does lasso keep?
  3. Train logistic regression, then move the decision threshold from 0.5 to 0.3 and observe precision and recall.
