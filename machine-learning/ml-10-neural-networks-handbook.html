Neural networks from the ground up

Deep learning is built from one repeating idea: stack simple units, measure the error, and nudge every weight to reduce it. This step explains each piece, runs a network by hand in NumPy, and gives you the training rules of thumb that prevent most failures.

1. From a neuron to a network

A neuron computes a weighted sum of its inputs plus a bias, then applies an activation function: output = f(w . x + b). A layer is many neurons in parallel (a matrix multiplication, step 02). A multilayer perceptron (MLP) stacks layers, so each layer builds more abstract features from the one before.

TermMeaning
Input layerThe features
Hidden layersLearned intermediate representations; "deep" means many
Output layerPrediction: one number (regression), one sigmoid unit (binary), or softmax over classes
Weights and biasesThe parameters learned in training
EpochOne full pass over the training data
BatchThe number of rows used for each weight update
Learning rateThe step size of each update

Without a non-linear activation, any stack of layers collapses into one linear model. The activation is what lets a network represent curves, interactions and complex patterns.

2. Activation functions

FunctionRangeUseNotes

TaskOutput layerLoss

3. Forward pass and backpropagation

  1. Forward pass: push a batch through the layers to get predictions.
  2. Loss: compare predictions with targets to get a single number.
  3. Backward pass (backpropagation): apply the chain rule (step 02) from the loss backwards to find the gradient of the loss for every weight.
  4. Update: an optimiser moves each weight a small step against its gradient.
  5. Repeat for every batch and epoch.

Frameworks compute gradients automatically (autograd), but writing it once by hand removes the mystery. A tiny network learning XOR, which no linear model can:

import numpy as np
rng = np.random.default_rng(0)
X = np.array([[0, 0], [0, 1], [1, 0], [1, 1]], float)
y = np.array([[0], [1], [1], [0]], float)

W1, b1 = rng.normal(0, 1, (2, 8)), np.zeros(8)
W2, b2 = rng.normal(0, 1, (8, 1)), np.zeros(1)
sigmoid = lambda z: 1 / (1 + np.exp(-z))
lr = 0.5

for epoch in range(5000):
    h = np.tanh(X @ W1 + b1)              # forward: hidden layer
    p = sigmoid(h @ W2 + b2)              # forward: output probability
    dz2 = (p - y) / len(X)                # backward: d(loss)/d(logit) for binary cross-entropy
    dW2, db2 = h.T @ dz2, dz2.sum(0)
    dz1 = (dz2 @ W2.T) * (1 - h ** 2)     # chain rule through tanh
    dW1, db1 = X.T @ dz1, dz1.sum(0)
    W1 -= lr * dW1; b1 -= lr * db1        # update
    W2 -= lr * dW2; b2 -= lr * db2

print(p.round(3).ravel())                 # close to [0, 1, 1, 0]

Why deep networks are hard to train

  • Vanishing gradients: gradients shrink as they pass back through many saturating layers, so early layers barely learn. ReLU-style activations, good initialisation, normalisation layers and residual connections address this.
  • Exploding gradients: the opposite; fix with gradient clipping (clip_grad_norm_).
  • Initialisation: use He initialisation for ReLU and Xavier for tanh and sigmoid (frameworks do this by default); never initialise all weights to the same value.

4. Optimisers, learning rate and batches

OptimiserIdeaWhen
SGD (with momentum)Plain gradient step plus a running average of past stepsVision models with careful tuning; best generalisation when tuned
RMSpropScales steps by a running average of gradient sizeSome recurrent networks
AdamMomentum plus per-parameter adaptive step sizesStrong default; start at lr 1e-3
AdamWAdam with decoupled weight decayThe standard for transformers and most modern training
  • Learning rate is the most important hyperparameter. Too high: the loss jumps or becomes NaN. Too low: training crawls.
  • Schedules: warm up for the first steps, then decay (cosine or one-cycle). Almost every large model uses this.
  • Batch size: 32 to 256 is typical; larger batches give smoother gradients and better hardware use, but may need a higher learning rate and can generalise slightly worse.
  • Epochs: train until validation loss stops improving, and use early stopping to keep the best checkpoint.

5. Regularisation and normalisation

TechniqueWhat it does
Weight decay (L2)Penalises large weights; use AdamW's decoupled version
DropoutRandomly zeroes activations during training, so units cannot over-rely on each other (typical 0.1 to 0.5)
Early stoppingStops when validation loss stops improving
Batch normalisationNormalises layer inputs per batch; speeds training in CNNs
Layer normalisationNormalises per example; standard in transformers
Data augmentationCreates varied training examples (flips, crops, noise, text perturbations)
Smaller model / more dataOften the real fix for overfitting

6. A training checklist that prevents most failures

  1. Overfit one small batch first. If the model cannot reach near-zero loss on 10 rows, there is a bug (wrong loss, labels, shapes or learning rate).
  2. Check the starting loss: for K balanced classes it should be about ln(K).
  3. Confirm inputs are scaled or normalised and labels line up with inputs.
  4. Watch both training and validation loss every epoch; the gap tells you overfitting from underfitting (step 08).
  5. Change one thing at a time and log every run.
  6. Set seeds and keep a simple baseline (linear model, gradient boosting) to compare against.
