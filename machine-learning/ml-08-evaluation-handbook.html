Evaluation, validation and tuning

Choosing the right metric and validating honestly is where most ML projects are won or lost. This step covers how to measure a model, diagnose why it fails, tune it without fooling yourself, and explain what it learned.

MetricsValidationBias and varianceTuningImbalanceCalibrationInterpretation

1. Regression metrics

MetricMeaningUse when
MAEAverage absolute error, in target unitsEasy to explain; robust to outliers
RMSESquare root of mean squared error, in target unitsLarge errors should hurt more
R-squaredShare of variance explained; 1 is perfect, 0 equals predicting the meanComparing models on the same data; can be negative
MAPE / sMAPEPercentage errorRelative error matters; breaks when true values are near zero
Pinball lossQuantile accuracyPrediction intervals

Always compare against a baseline such as the mean or last observation. An RMSE of 12 means nothing without knowing the baseline is 13 or 40.

2. Classification metrics

Every classification metric derives from the confusion matrix: true positives (TP), false positives (FP), false negatives (FN) and true negatives (TN).

MetricFormula ideaAnswersUse when
Accuracy(TP + TN) / allHow often is it right?Balanced classes and equal costs only
PrecisionTP / (TP + FP)Of predicted positives, how many are real?False alarms are costly (spam sent to junk)
Recall (sensitivity)TP / (TP + FN)Of real positives, how many did we catch?Misses are costly (disease, fraud)
F1 / F-betaHarmonic mean of precision and recallA single balance; beta above 1 favours recallImbalanced data, one number needed
ROC-AUCRanking quality across all thresholdsCan it rank positives above negatives?Comparing models; balanced-ish data
PR-AUC (average precision)Precision vs recall across thresholdsQuality on the rare classHeavily imbalanced data
Log lossPenalises confident wrong probabilitiesHow good are the probabilities?You use the probabilities directly
Matthews correlation (MCC)Balanced single score from the confusion matrixOverall quality with imbalanceA robust single number
from sklearn.metrics import (classification_report, confusion_matrix, roc_auc_score,
                             average_precision_score, ConfusionMatrixDisplay)

proba = model.predict_proba(X_test)[:, 1]
pred = proba >= 0.4                                     # your chosen threshold
print(classification_report(y_test, pred, digits=3))
print(confusion_matrix(y_test, pred))
print("ROC-AUC", roc_auc_score(y_test, proba), "PR-AUC", average_precision_score(y_test, proba))
  • Threshold: models output scores; the 0.5 cut-off is arbitrary. Pick the threshold from the cost of each kind of error or the team's review capacity.
  • Multiclass: average per-class metrics with macro (every class equal), weighted (by support) or micro (pooled).
  • Ranking and recommendation: precision@k, recall@k, NDCG and MAP. Clustering: see step 07.
  • Business metric: convert errors to money or time and report that alongside the technical metric.

3. Validation strategies

StrategyHowUse when
Hold-outOne train/validation/test splitPlenty of data; a quick check
K-fold cross-validationTrain on k-1 folds, validate on the rest, rotate; averageSmall to medium data; the default
Stratified K-foldFolds keep class proportionsClassification, especially imbalanced
Group K-foldAll rows of a group stay in one foldMany rows per patient, user, device
Time series splitAlways train on the past, validate on the futureForecasting and any time-dependent data
Nested cross-validationTune in an inner loop, evaluate in an outer loopAn honest estimate when tuning many choices on small data
from sklearn.model_selection import cross_validate, StratifiedKFold

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
res = cross_validate(model, X, y, cv=cv, scoring=["roc_auc", "average_precision", "f1"],
                     return_train_score=True, n_jobs=-1)
for k in ("test_roc_auc", "test_average_precision", "test_f1"):
    print(k, res[k].mean().round(3), "+/-", res[k].std().round(3))
Keep the test set sacredUse cross-validation to compare and tune. Touch the final test set once, to report the number. Every time you look at it and change something, it becomes part of training.

4. Bias, variance and diagnosing problems

SymptomDiagnosisWhat to try
Poor train score and poor validation scoreHigh bias (underfitting)More expressive model, better features, less regularisation, train longer
Great train score, much worse validation scoreHigh variance (overfitting)More data, stronger regularisation, simpler model, fewer features, early stopping, ensembling
Good validation, poor productionLeakage or driftAudit features and splits; check data distribution changes

A learning curve (score against training-set size) tells you whether more data would help: if the validation score is still rising, yes. A validation curve (score against one hyperparameter) shows where the model moves from underfitting to overfitting.

from sklearn.model_selection import learning_curve
sizes, tr, va = learning_curve(model, X, y, cv=5, scoring="roc_auc",
                               train_sizes=[0.1, 0.25, 0.5, 0.75, 1.0], n_jobs=-1)
print(tr.mean(axis=1), va.mean(axis=1))

5. Hyperparameter tuning

MethodHowUse when
Grid searchTry every combinationFew parameters, small ranges
Random searchSample combinations at randomThe default for many parameters; beats grid for the same budget
Successive halvingTry many cheaply, keep the best, give them more resourcesLarge search spaces, limited compute
Bayesian optimisation (Optuna, Hyperopt)Uses past trials to choose the nextExpensive models such as boosting and neural networks
import optuna
from sklearn.model_selection import cross_val_score
from sklearn.ensemble import HistGradientBoostingClassifier

def objective(trial):
    m = HistGradientBoostingClassifier(
        learning_rate=trial.suggest_float("lr", 0.01, 0.3, log=True),
        max_leaf_nodes=trial.suggest_int("leaves", 8, 64),
        min_samples_leaf=trial.suggest_int("min_leaf", 10, 100),
        l2_regularization=trial.suggest_float("l2", 1e-3, 10, log=True))
    return cross_val_score(m, X_train, y_train, cv=5, scoring="roc_auc").mean()

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=50)
print(study.best_params)
  • Tune the whole pipeline (preprocessing included) so every fold is leak-free.
  • Search learning rates and regularisation on a log scale.
  • Set a budget. Past a point, tuning gains are smaller than the noise in your validation score.
  • Track experiments with MLflow or Weights & Biases (see the MLflow handbook).

6. Imbalanced data

When one class is rare (fraud, churn, defects), accuracy is misleading: predicting "never fraud" scores 99.9% and is useless. Work through this order:

  1. Use the right metrics: PR-AUC, recall at a fixed precision, F-beta.
  2. Use stratified splits so every fold contains positives.
  3. Try class weights (class_weight="balanced", scale_pos_weight); cheap and often enough.
  4. Tune the decision threshold for the business cost.
  5. Consider resampling (random under-sampling, SMOTE from imbalanced-learn), only inside cross-validation folds and never on the test set.
  6. Collect more minority examples if you can; it beats every trick.

7. Probability calibration

A well-calibrated model that says 30% should be right about 30% of the time. Boosted trees, random forests and SVMs often are not. Calibrate when you use the probabilities directly (pricing, risk scores, expected-value decisions).

from sklearn.calibration import CalibratedClassifierCV, calibration_curve
cal = CalibratedClassifierCV(model, method="isotonic", cv=5).fit(X_train, y_train)
frac_pos, mean_pred = calibration_curve(y_test, cal.predict_proba(X_test)[:, 1], n_bins=10)

Use sigmoid (Platt scaling) for small data and isotonic with plenty of data.

8. Interpreting models

TechniqueScopeNotes
Coefficients / odds ratiosGlobal, linear modelsScale features to compare them
Permutation importanceGlobal, any modelShuffle a feature and see how much the score drops; compute on held-out data
Partial dependence and ICE plotsGlobal and individualAverage effect of one feature; misleading with correlated features
SHAP valuesGlobal and per-predictionAttributes each prediction to features; fast exact version for trees
LIMEPer-predictionLocal linear approximation; less stable than SHAP
Error analysisSlices of dataWhere does the model fail: which segments, which classes?
import shap
from sklearn.inspection import permutation_importance

pi = permutation_importance(model, X_val, y_val, scoring="roc_auc", n_repeats=10, random_state=0)
explainer = shap.TreeExplainer(model)          # tree models
shap_values = explainer(X_val)
shap.plots.beeswarm(shap_values)

Interpretation shows what the model uses, not what causes the outcome. Also check performance across subgroups (age, region, language) for fairness, and document limits in a model card (see the AI governance handbooks).

Practice
  1. Take a classification model, plot its precision-recall curve and choose a threshold that gives at least 80% precision.
  2. Compare 5-fold stratified CV with a single random split across ten random seeds. How much do they vary?
  3. Run permutation importance and SHAP on the same model and note any disagreement.
