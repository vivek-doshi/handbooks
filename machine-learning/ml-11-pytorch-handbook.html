Deep learning with PyTorch

PyTorch is the dominant framework for deep learning research and most production work. This step turns the ideas of step 10 into runnable code: a complete, correct training loop you can adapt to almost any task.

1. Tensors

A tensor is an n-dimensional array like NumPy's, with two extras: it can live on a GPU and it can track gradients. Install from pytorch.org with the command for your platform (CPU or CUDA).

import torch

x = torch.tensor([[1., 2.], [3., 4.]])
print(x.shape, x.dtype, x.device)
y = x @ x.T + 1                    # matrix multiply and broadcasting
z = torch.from_numpy(x.numpy())    # share memory with NumPy (CPU only)

device = ("cuda" if torch.cuda.is_available()
          else "mps" if torch.backends.mps.is_available() else "cpu")
x = x.to(device)
  • Shapes are the main source of bugs: print them often. Common layout is (batch, features) for tables, (batch, channels, height, width) for images and (batch, sequence, features) for sequences.
  • Data types: float32 for inputs, long (int64) for class labels used with cross-entropy.
  • Move the model and every batch to the same device.

2. Autograd: automatic gradients

w = torch.tensor(2.0, requires_grad=True)
loss = (w * 3 - 12) ** 2           # builds a computation graph
loss.backward()                    # fills w.grad with d(loss)/dw
print(w.grad)                      # 2 * (6 - 12) * 3 = -36

with torch.no_grad():              # no graph: use for evaluation and manual updates
    w -= 0.01 * w.grad
w.grad.zero_()                     # gradients accumulate, so reset them

Gradients accumulate across backward() calls. Forgetting to zero them in a training loop is a classic bug.

3. Building models with nn.Module

A model is a class that creates layers in __init__ and defines the forward computation in forward. PyTorch tracks all parameters automatically.

import torch.nn as nn

class MLP(nn.Module):
    def __init__(self, n_in, n_hidden, n_out, p=0.2):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_in, n_hidden), nn.ReLU(), nn.Dropout(p),
            nn.Linear(n_hidden, n_hidden), nn.ReLU(), nn.Dropout(p),
            nn.Linear(n_hidden, n_out))          # raw logits out

    def forward(self, x):
        return self.net(x)

model = MLP(20, 128, 3).to(device)
print(sum(p.numel() for p in model.parameters()), "parameters")

4. Datasets and DataLoaders

A Dataset returns one example; a DataLoader batches, shuffles and loads in parallel.

from torch.utils.data import Dataset, DataLoader, random_split

class TabularDataset(Dataset):
    def __init__(self, X, y):
        self.X = torch.as_tensor(X, dtype=torch.float32)
        self.y = torch.as_tensor(y, dtype=torch.long)
    def __len__(self):
        return len(self.X)
    def __getitem__(self, i):
        return self.X[i], self.y[i]

ds = TabularDataset(X_scaled, y)
train_ds, val_ds = random_split(ds, [0.8, 0.2], generator=torch.Generator().manual_seed(0))
train_dl = DataLoader(train_ds, batch_size=64, shuffle=True, num_workers=2, pin_memory=True)
val_dl = DataLoader(val_ds, batch_size=256)

Fit scalers on the training split only (step 03). For images, torchvision.datasets and transforms provide ready-made datasets and augmentation; for text and audio see Hugging Face datasets.

5. The training loop

The loop is the same for almost every task: forward, loss, zero gradients, backward, step. Switch to model.eval() and torch.no_grad() for validation so dropout and batch normalisation behave correctly.

loss_fn = nn.CrossEntropyLoss()
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-2)
sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=30)

def run_epoch(dl, train):
    model.train(train)
    total, correct, n = 0.0, 0, 0
    for xb, yb in dl:
        xb, yb = xb.to(device), yb.to(device)
        with torch.set_grad_enabled(train):
            logits = model(xb)
            loss = loss_fn(logits, yb)
        if train:
            opt.zero_grad(set_to_none=True)
            loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step()
        total += loss.item() * len(xb)
        correct += (logits.argmax(1) == yb).sum().item()
        n += len(xb)
    return total / n, correct / n

best, patience = float("inf"), 0
for epoch in range(30):
    tr_loss, tr_acc = run_epoch(train_dl, True)
    va_loss, va_acc = run_epoch(val_dl, False)
    sched.step()
    print(f"{epoch:02d} train {tr_loss:.3f}/{tr_acc:.3f}  val {va_loss:.3f}/{va_acc:.3f}")
    if va_loss < best:
        best, patience = va_loss, 0
        torch.save(model.state_dict(), "best.pt")
    else:
        patience += 1
        if patience == 5:
            break                      # early stopping

6. GPUs, mixed precision and speed

  • Mixed precision: run most maths in bfloat16 or float16 for speed and memory. In PyTorch, wrap the forward pass and loss in torch.autocast(device_type="cuda", dtype=torch.bfloat16). (float16 also needs a gradient scaler.)
  • torch.compile: model = torch.compile(model) in PyTorch 2.x fuses operations for faster training and inference; try it once the model works.
  • Data loading: raise num_workers and set pin_memory=True if the GPU is idle.
  • Memory: lower the batch size, use gradient accumulation, or mixed precision. Use torch.inference_mode() when predicting.
  • Reproducibility: torch.manual_seed(0); bit-exact results need deterministic settings and may cost speed.
  • No GPU? Use free notebook GPUs or the cloud (see the cloud AI steps) rather than waiting on a CPU.
with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
    logits = model(xb)
    loss = loss_fn(logits, yb)
loss.backward()

7. Saving, loading and the wider ecosystem

torch.save(model.state_dict(), "model.pt")            # save weights, not the whole object

model = MLP(20, 128, 3)
state = torch.load("model.pt", map_location="cpu", weights_only=True)   # safe loading
model.load_state_dict(state)
model.eval()
with torch.inference_mode():
    probs = torch.softmax(model(torch.randn(1, 20)), dim=1)
  • Never load checkpoints from untrusted sources; pickle can execute code. Prefer weights_only=True or the safetensors format.
  • Save the optimiser and epoch too when you want to resume training.
  • Export for serving with ONNX or TorchScript-style paths, or serve directly with a model server.
