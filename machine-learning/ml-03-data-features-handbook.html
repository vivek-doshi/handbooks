Data preparation and feature engineering

Model quality is capped by data quality. This step covers the unglamorous work that decides most results: understanding the data, cleaning it, turning it into numbers, and splitting it so your scores can be trusted.

ExploreMissing valuesEncodingScalingFeature engineeringSplitting and leakage

1. Explore before you model

Spend time with the data first. For pandas fundamentals see the pandas handbook; for pipelines that deliver the data see the ETL handbook.

import pandas as pd

df = pd.read_csv("customers.csv")
print(df.shape)
print(df.dtypes)
print(df.describe(include="all").T)
print(df.isna().mean().sort_values(ascending=False).head(10))   # share missing
print(df["churned"].value_counts(normalize=True))                # target balance
print(df.duplicated().sum())

2. Missing values and outliers

StrategyWhen to use
Drop rowsFew rows missing and missing at random
Drop columnMostly empty and not informative
Impute median or meanNumeric, missing at random; median is safer with outliers
Impute most frequent or a constantCategorical columns
Add a was_missing indicatorMissingness itself carries signal (income not provided)
Model-based imputation (KNN, iterative)Strong relationships between features; costs more
Leave itTree-based models such as HistGradientBoosting, XGBoost and LightGBM handle NaN natively

Always fit the imputer on training data only. Otherwise statistics from the test set leak into training.

  • Outliers: find them with box plots or the 1.5 x IQR rule, then decide. Errors get fixed or removed; genuine extremes are kept, and you choose robust methods (median, trees, Huber loss) or transform them (log).
  • Do not remove outliers just because they hurt the score; they may be exactly the cases you need to predict.

4. Scaling and transforming numbers

MethodFormula ideaUse when
Standardisation(x - mean) / stdDefault for linear models, SVM, KNN, PCA, neural networks
Min-maxRescale to 0 to 1Bounded inputs; image pixels
Robust scaling(x - median) / IQRMany outliers
Log or power transformlog(1 + x), Yeo-JohnsonRight-skewed values such as prices and counts
Who needs scaling?Distance-based and gradient-based models (KNN, SVM, k-means, PCA, linear models with regularisation, neural networks) need scaled features. Tree-based models (decision tree, random forest, gradient boosting) do not.

5. Feature engineering

Good features usually beat clever algorithms. Common patterns:

  • Dates: extract day of week, month, hour, is-weekend, days since an event; use cyclic encodings (sin and cos) for hour or month.
  • Ratios and differences: debt-to-income, price per square metre, change since last period.
  • Aggregations: per-customer averages, counts in the last 30 days, time since last purchase. Compute them using only information available at prediction time.
  • Interactions and polynomials: products of features that matter together. Trees find interactions on their own; linear models need them added.
  • Binning: turn age into bands when the effect is stepwise.
  • Text: bag-of-words and TF-IDF for classical models, or embeddings (step 13).
  • Domain knowledge: talk to the people who know the data. This is often the highest-value step.

Feature selection removes noise and speeds training: drop constant or duplicate columns, check high correlation between features, use L1 regularisation (step 04), tree importances or permutation importance (step 08), or recursive feature elimination (RFE).

6. Splitting data and avoiding leakage

SplitPurposeRule
TrainFit the modelEverything you learn comes from here
Validation (or cross-validation folds)Choose models and hyperparametersLook at it as often as needed
TestFinal unbiased estimateUse once at the end; never tune on it
  • Stratified split keeps class proportions: use stratify=y for classification.
  • Time-based split for anything that changes over time: train on the past, test on the future. Random splits leak the future.
  • Group split when rows share an entity (many rows per patient or customer): keep each group wholly in one split.

Data leakage: the most common reason a great model fails in production

LeakExampleFix
Target leakageA feature recorded after the outcome, such as "refund issued" when predicting churnAsk, for every feature: is it known at prediction time?
Preprocessing leakageScaling or imputing before splittingFit all preprocessing inside a pipeline on training data only
Duplicate or near-duplicate rowsSame record in train and testDeduplicate; group split
Temporal leakageRandom split of time-ordered dataTime-based split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

num = ["age", "tenure", "monthly_spend"]
cat = ["plan", "region"]

pre = ColumnTransformer([
    ("num", Pipeline([("impute", SimpleImputer(strategy="median")),
                      ("scale", StandardScaler())]), num),
    ("cat", Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                      ("onehot", OneHotEncoder(handle_unknown="ignore"))]), cat),
])
model = Pipeline([("pre", pre), ("clf", LogisticRegression(max_iter=1000))])

X_train, X_test, y_train, y_test = train_test_split(
    df[num + cat], df["churned"], test_size=0.2, stratify=df["churned"], random_state=42)
model.fit(X_train, y_train)          # preprocessing is fitted on training data only
Practice
  1. Take any CSV you have, list missing values per column and decide a strategy for each.
  2. Ask of every feature: would I know this at the moment of prediction? Remove any that fail.
  3. Build the pipeline above on your data and compare it to a DummyClassifier baseline.
