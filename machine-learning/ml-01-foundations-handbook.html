Machine learning foundations

Machine learning is a way to build software whose behaviour is learned from examples instead of written as rules. This first step gives you the vocabulary, the project workflow and a working first model, so every later algorithm has somewhere to fit.

1. What machine learning is

In traditional programming you write rules and feed in data to get answers. In machine learning you feed in data and the known answers, and the algorithm works out the rules. Those learned rules are called a model.

TermMeaningExample
Artificial intelligenceAny technique that makes machines act intelligentlySearch, planning, rules, ML
Machine learningSystems that improve at a task from dataSpam filter, price prediction
Deep learningML using many-layered neural networksImage recognition, speech
Generative AIDeep models that produce text, images or codeChat assistants, image generators

This path covers classical ML (steps 01 to 09) and deep learning up to the transformer (steps 10 to 13). Generative AI, LLM applications and agents are covered in the gen-ai handbooks, and they build directly on step 13.

2. When to use ML, and when not to

ML is the right tool when the rules are too many or too fuzzy to write by hand, and you have enough representative data with outcomes you can measure.

Use ML whenDo not use ML when
The pattern is hard to describe in rules (fraud, churn, image content)A clear rule or SQL query solves it (tax rate, eligibility threshold)
You have many labelled examples, or a way to get themYou have almost no data and cannot collect any
Conditions change and the system must adaptA wrong answer is unacceptable and must be explainable by law, with no review step
An approximate answer is valuable at scaleA simple average or heuristic is already good enough
Always build a baseline firstBefore any model, measure the simplest thing that could work: the majority class, the historical average, last week's value, or a hand-written rule. A model is only worth deploying if it clearly beats that baseline.

3. Types of learning

TypeLearns fromGoalTypical tasks
SupervisedInputs with known answers (labels)Predict the label for new inputsRegression (a number), classification (a category)
UnsupervisedInputs onlyFind structureClustering, dimensionality reduction, anomaly detection
Semi-supervisedA few labels plus many unlabelled rowsUse cheap unlabelled dataDocument or image labelling
Self-supervisedLabels derived from the data itselfLearn general representationsPredict the next word; foundation models
ReinforcementRewards from interacting with an environmentLearn a policyGames, robotics, ranking and RLHF-style tuning

Most business ML is supervised. Roughly: if the target is a number it is regression; if it is a category it is classification; if there is no target it is unsupervised.

4. Core terminology

TermMeaning
Sample / rowOne example (a customer, an image, a transaction)
Feature / columnOne input measurement about a sample
Target / labelThe answer we want to predict
ModelThe function learned from data that maps features to predictions
ParametersValues the algorithm learns itself (weights, split thresholds)
HyperparametersSettings you choose before training (tree depth, learning rate)
Loss functionA number that measures how wrong the predictions are; training tries to minimise it
Training / inferenceFitting the model to data / using it to predict on new data
GeneralisationPerforming well on data the model has never seen
OverfittingMemorising noise in the training data; great training score, poor test score
UnderfittingToo simple to capture the pattern; poor on both training and test data
Data leakageInformation from outside the training period or from the target slipping into the features, giving falsely good results

5. The ML workflow

  1. Frame the problem. What decision will the prediction change? What is the target? How will success be measured in business terms?
  2. Collect and understand the data. Sources, quality, volume, and whether it matches what you will see in production.
  3. Split the data into train, validation and test before looking for patterns (step 03).
  4. Set a baseline and choose the evaluation metric (step 08).
  5. Prepare features and build a first simple model (steps 03 to 05).
  6. Try stronger models, tune and compare using cross-validation (steps 06 to 09).
  7. Evaluate once on the test set, inspect errors and check fairness and robustness.
  8. Deploy and monitor. Data drifts and models decay; production is the start, not the end (see the MLOps handbook).

Real projects loop through these steps many times. Most of the time is spent on steps 1 to 3, not on algorithms.

6. Your environment and first model

Use a virtual environment per project (python -m venv .venv, or a tool such as uv), a notebook or editor, and the core libraries: NumPy, pandas, matplotlib and scikit-learn.

python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install numpy pandas matplotlib scikit-learn jupyterlab

A complete first model: classify iris flowers, with a proper train/test split and a baseline for comparison.

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

baseline = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
model = LogisticRegression(max_iter=1000).fit(X_train, y_train)

print("baseline:", accuracy_score(y_test, baseline.predict(X_test)))
print("model   :", accuracy_score(y_test, model.predict(X_test)))

Every scikit-learn model follows the same pattern: create it, call fit on training data, then call predict on new data. That consistency is why this path can cover many algorithms quickly.

Practice
  1. Install the environment above and run the iris example.
  2. Change test_size and random_state and note how much the accuracy moves. That variation is why a single split is not enough (step 08).
  3. Write down one decision in your own work where an ML model could help, and what the baseline would be.
