Experiment Tracking and Model Registry

Experiments are cheap only if you can compare them later. Tracking records what was run; the registry records which model is approved for which stage.

BeginnerMLflowW&B

What to track

  • Parameters, metrics (per step), tags, code version (git SHA), data version (DVC or snapshot id), environment, hardware, seed.
  • Artifacts: model files, plots, confusion matrices, sample predictions.
  • Evaluation reports and the dataset used for them.

MLflow tracking

import mlflow, mlflow.sklearn
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import f1_score

mlflow.set_tracking_uri("http://mlflow.internal:5000")   # shared server, not local files
mlflow.set_experiment("churn")

with mlflow.start_run(run_name="rf-baseline"):
    mlflow.set_tags({"git_sha": GIT_SHA, "data_version": DATA_REV})
    params = {"n_estimators": 300, "max_depth": 12}
    mlflow.log_params(params)
    model = RandomForestClassifier(**params).fit(X_train, y_train)
    mlflow.log_metric("f1", f1_score(y_val, model.predict(X_val)))
    mlflow.sklearn.log_model(model, name="model", input_example=X_val[:5])

mlflow.autolog() captures most of this for common libraries. Always set the tracking URI explicitly; a silent local mlruns folder is the classic pitfall. Parameter names such as name versus artifact_path in log_model vary by MLflow version; check your docs.

Model registry and lifecycle

  • The registry is a catalogue of model versions with lineage back to the run, data and code.
  • Use aliases (for example champion, challenger) and tags instead of the older fixed stages; deployment code loads models:/churn@champion.
  • Attach a model card: purpose, data, metrics by segment, limits, owner, approval record.
from mlflow import MlflowClient
c = MlflowClient()
mv = mlflow.register_model(f"runs:/{run_id}/model", "churn")
c.set_registered_model_alias("churn", "challenger", mv.version)
# after validation gates pass:
c.set_registered_model_alias("churn", "champion", mv.version)
model = mlflow.pyfunc.load_model("models:/churn@champion")

A model signature (input and output schema) lets serving reject malformed requests.

  • Strengths: rich dashboards, sweeps for hyperparameter search, artifacts with lineage, reports for collaboration.
  • Pitfalls: network stalls from logging too often, orphaned runs, artifact bloat. Log at intervals and set retention.
  • Choose MLflow when you want open source and self-hosting with a registry; W&B for rich collaboration; both can coexist.

A promotion workflow

train run -> evaluation job (held-out + slice metrics + fairness + latency)
  -> compare with champion -> gate: better by margin, no slice regression, passes tests
  -> register as challenger -> shadow or canary in staging/prod -> approve -> alias champion

Practice

Practice
  1. Log three runs with different params in MLflow and compare them in the UI.
  2. Register the best one and load it by alias from a separate script.
