Model Serving and Deployment

Deployment is choosing the right serving pattern and releasing it safely. The pattern depends on latency, volume and freshness needs.

IntermediateKServeCanary and shadow

Serving patterns

PatternLatencyUse forNotes
Batch scoringMinutes to hoursRecommendations lists, churn scores, forecastsCheapest; write results to a table
Online (request-response)Milliseconds to secondsFraud, ranking, chatAutoscaled service, needs online features
StreamingSub-second on eventsAnomaly detection, IoTFlink or Kafka consumers calling the model
Embedded or edgeLocalMobile, devices, offlineONNX, TFLite, quantised models
Async jobSeconds to minutesLarge documents, videoQueue plus workers
DefaultPrefer batch when freshness allows. Online serving multiplies cost, on-call load and skew risk.

A minimal online service

from fastapi import FastAPI
from pydantic import BaseModel
import mlflow.pyfunc

app = FastAPI()
model = mlflow.pyfunc.load_model("models:/churn@champion")   # pinned at start, logged

class Req(BaseModel):
    tenure: float
    monthly_spend: float

@app.post("/predict")
def predict(r: Req):
    p = float(model.predict([[r.tenure, r.monthly_spend]])[0])
    return {"score": p, "model_version": MODEL_VERSION}

@app.get("/healthz")
def health(): return {"ok": True}

Production images run with multiple workers, health and readiness probes, timeouts and request logging of inputs and outputs for monitoring.

Release strategies

StrategyHowRisk covered
ShadowSend live traffic to the new model, discard its output, compareBehaviour and latency with zero user impact
CanaryRoute 1 to 10 percent, watch metrics, rampRegression on real traffic
Blue-greenSwitch all traffic between two stacksFast rollback
A/B testRandomised split measuring a business metricReal value, not just offline metrics
Multi-armed banditShift traffic to the better variant adaptivelyCost of exploring
  • Define automatic rollback conditions before the rollout.
  • Offline gains often do not translate; the A/B test is the arbiter.

Performance and cost

  • Batching and dynamic batching on GPUs; concurrency tuned with load tests.
  • Quantisation (INT8, FP8), distillation, ONNX or TensorRT compilation; verify accuracy afterwards.
  • Autoscale on queue depth or latency, scale to zero for rare models, share GPUs (MIG, multi-model serving).
  • Cache repeated predictions where inputs repeat.
