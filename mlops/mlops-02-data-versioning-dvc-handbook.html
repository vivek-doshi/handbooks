Step 02 · Beginner · Version the data

Data Versioning with DVC

Git cannot hold gigabytes. DVC keeps small pointer files in Git and the actual data in object storage, so every commit identifies exact code and exact data.

BeginnerDVCReproducibility

Why version data

  • A model is a function of code and data. Without data versions you cannot reproduce or audit it.
  • Rollback: restore the dataset that produced the last good model.
  • Collaboration: teammates fetch the same data by checking out a commit.

DVC basics

pip install dvc[s3]            # or [gs], [azure]
git init && dvc init
dvc remote add -d storage s3://my-bucket/dvcstore
dvc add data/raw.csv           # creates data/raw.csv.dvc, ignores the file in git
git add data/raw.csv.dvc data/.gitignore .dvc/config
git commit -m "Track raw data v1"
dvc push                       # upload data to the remote

# teammate or CI
git clone <repo> && dvc pull   # fetch exact data for this commit
git checkout v1.0 && dvc checkout   # switch data with code
  • Use shared remotes with least-privilege credentials; enable bucket versioning as a safety net.
  • DVC caches by content hash, so identical files are stored once.
  • Never commit the data or the secrets; commit the .dvc files and dvc.lock.

DVC pipelines

# dvc.yaml
stages:
  prepare:
    cmd: python src/prepare.py data/raw.csv data/prepared
    deps: [src/prepare.py, data/raw.csv]
    outs: [data/prepared]
  train:
    cmd: python src/train.py data/prepared models/model.pkl
    deps: [src/train.py, data/prepared]
    params: [train.lr, train.n_estimators]
    outs: [models/model.pkl]
    metrics: [metrics.json: {cache: false}]

# run only what changed
dvc repro
dvc metrics diff main
dvc params diff

DVC builds a graph from deps and outs and re-runs only stages whose inputs changed. The dvc.lock file pins exact hashes, giving a reproducible run.

Experiments

dvc exp run -S train.lr=0.01          # run a variation without committing
dvc exp show                            # table of params and metrics
dvc exp apply <name> && git commit      # promote the winner

DVC experiments are lightweight; for team dashboards, collaboration and registries pair DVC with MLflow or W&B (step 03).

Beyond a laptop

  • For petabyte lakes do not copy data into DVC; reference it with dvc import-url or use table-format snapshots (Iceberg or Delta version ids) and record the snapshot id in the run.
  • Use lakeFS or object-store versioning when many pipelines write the same bucket.
  • Keep data contracts and schema checks next to the pointer (step 06).

Practice

Practice
  1. Track a dataset with DVC and a bucket remote, change it, and switch back with git checkout and dvc checkout.
  2. Build a two-stage dvc.yaml and observe dvc repro skipping unchanged stages.
