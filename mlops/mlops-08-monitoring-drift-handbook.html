Monitoring, Drift and Retraining

Models decay silently. Monitoring turns that into alerts and retraining decisions.

Kinds of drift

TypeMeaningExample
Data (covariate) driftInput distribution P(X) changesNew customer segment, sensor recalibration
Label driftTarget distribution changesFraud rate rises
Concept driftRelationship P(Y given X) changesBehaviour shifts after a pricing change
Upstream data changePipeline bug or schema changeCurrency unit changed

Drift in inputs does not always hurt accuracy, and accuracy can fall without visible input drift. Monitor both.

Detecting drift

import numpy as np
def psi(expected, actual, bins=10):
    edges = np.quantile(expected, np.linspace(0, 1, bins + 1))
    e = np.histogram(expected, edges)[0] / len(expected)
    a = np.histogram(np.clip(actual, edges[0], edges[-1]), edges)[0] / len(actual)
    e, a = np.clip(e, 1e-6, None), np.clip(a, 1e-6, None)
    return float(np.sum((a - e) * np.log(a / e)))
# rule of thumb: PSI < 0.1 stable, 0.1 to 0.25 watch, > 0.25 investigate
  • Numeric: PSI, Kolmogorov-Smirnov, Wasserstein distance.
  • Categorical: chi-square, Jensen-Shannon divergence.
  • Embeddings and text: domain classifier or embedding distance.
  • Compare production windows to the training reference and to the previous window.

Delayed and missing labels

  • Use proxy metrics now (prediction drift, user feedback) and true metrics when ground truth arrives (fraud chargebacks arrive weeks later).
  • Sample and label a slice of traffic with human reviewers.
  • Log predictions with ids so labels can be joined later.

Closing the loop

monitor -> alert (threshold + persistence) -> triage (data bug? real drift?)
   -> trigger retrain pipeline on fresh data -> challenger vs champion gates -> canary -> promote
Policy: retrain on schedule AND on drift; never auto-promote without gates
  • Alert on sustained deviations to avoid noise; page only for user-impacting issues.
  • Keep runbooks: rollback, fallback to rules or the previous model, disable feature.
  • Retraining on the newest data is not always better; evaluate on a recent holdout.
