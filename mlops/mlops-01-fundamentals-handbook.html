MLOps Fundamentals

A model in a notebook is about 5 percent of a production ML system. MLOps is the set of practices that makes the other 95 percent repeatable, testable and observable.

BeginnerLifecycleMaturity levels

What MLOps is

MLOps applies DevOps ideas (version control, automation, CI/CD, monitoring) to machine learning, and adds what is unique to ML: data and models are artifacts that change independently of code, and model quality decays as the world changes.

QuestionDevOps answerMLOps adds
What do we version?Code, configCode, data, features, models, experiments, prompts
What do we test?Code behaviourData quality, model quality, fairness, drift, latency
What triggers a release?A commitA commit, new data, a drift alert or a schedule
How does it fail?Crashes, errorsSilently: accuracy decays with no error
What do we monitor?Latency, errors, saturationPlus input drift, prediction drift, business outcome

Why ML projects stall

  • Training-serving skew: features computed differently offline and online.
  • No reproducibility: nobody can recreate last quarter's model.
  • Manual hand-offs: data scientists email notebooks to engineers.
  • Silent decay: no monitoring of data or model quality.
  • Data debt: unversioned, undocumented, unowned datasets.
  • Unclear ownership between data, ML, platform and product teams.

The ML lifecycle

Business problem -> Data (collect, validate, version) -> Features -> Experiment (train, evaluate, track)
   -> Package (model + code + env) -> Validate (gates) -> Deploy (batch / online / edge)
   -> Monitor (system, data, model, business) -> Retrain or retire -> back to Data

Each arrow should be automated and each box should produce a versioned artifact. The rest of this path takes these in order.

Maturity levels

LevelDescriptionSigns
0 ManualNotebooks, manual deployNo tracking, models rarely updated
1 Automated pipelineTraining is a pipeline; continuous training; tracked and registered modelsPipeline runs on schedule or trigger; deploy still reviewed
2 CI/CD for MLPipeline code is tested and deployed automatically; automated validation gates, monitoring feeds retrainingMany models, frequent safe releases

This follows the widely used Google and Microsoft MLOps maturity models. Target level 1 first; level 2 pays off when you run many models.

Core principles

  • Everything as code: pipelines, infrastructure, configs.
  • Reproducibility: code + data + environment + seed identify a model.
  • Automate the path to production, with human approval where risk demands.
  • Monitor the model, not just the server.
  • Start with the simplest thing that works; add platform pieces when pain appears.

Practice

Practice
  1. Take one model you know and list: where is its data, code, config, and evaluation stored? What would you lose if the laptop died?
  2. Place it on the maturity scale.
