Step 09 · Intermediate · What changes for LLMs

LLMOps: Operating GenAI and SLMs

LLM systems keep the lifecycle but swap the artifacts: prompts, retrieval indexes, adapters and evaluation sets become the things you version, test and monitor.

IntermediateLLMOpsTracing and evals

What changes

MLOpsLLMOps
Train from your dataMostly adapt or prompt a foundation model
Metrics like accuracyRubrics, LLM judges, groundedness, human review
Feature storeRetrieval index, context assembly
Model versionsModel + prompt + adapter + index versions together
Latency in msSeconds, streaming, token cost
Drift in featuresDrift in user queries, documents and provider model updates
SecurityPlus prompt injection, data leakage, tool permissions

For the application side see the Gen-AI evaluation and guardrails and architecture decisions handbooks.

What to version

  • Prompts and templates with ids in a registry; log the prompt version on every call.
  • Model identifiers (pinned provider versions) and adapter versions.
  • Retrieval index version, embedding model and chunking config.
  • Evaluation datasets and judge prompts.
  • Tool schemas and guardrail policies.

Tracing and evaluation

from langsmith import traceable, Client
from langsmith.evaluation import evaluate

@traceable(name="rag_answer")
def rag_answer(question: str) -> str:
    ctx = retrieve(question)
    return generate(question, ctx)

def grounded(run, example):           # custom evaluator
    return {"key": "grounded", "score": judge_grounded(run.outputs["output"], example.inputs)}

evaluate(lambda inp: {"output": rag_answer(inp["question"])},
         data="support-golden-v3", evaluators=[grounded], experiment_prefix="prompt-v12")
  • LangSmith, Langfuse, Arize Phoenix, MLflow GenAI and W&B Weave provide tracing, datasets, experiments and online evaluation.
  • Run the golden set in CI; sample production traces for online scoring and human review.
  • OpenTelemetry GenAI conventions make traces portable.

Fine-tuning as a pipeline

curate data (versioned) -> filter + dedupe -> split -> train (LoRA/QLoRA) -> eval vs prompted baseline + regression
 -> register adapter + model card -> deploy (vLLM multi-LoRA) -> canary -> monitor -> collect feedback -> next data version

The method details are in fine-tuning fundamentals and in practice. Use case 4 in step 13 shows the full MLOps pipeline for an SLM.

Operations

  • Pin provider model versions and re-run evals before upgrading; providers deprecate models on a schedule.
  • Gateway with budgets, rate limits, fallbacks and caching.
  • Cost per resolved task as the main efficiency metric.
  • Red-team and guardrail tests as release gates.

Practice

Practice
  1. Add tracing to an LLM app and find the most expensive span.
  2. Build a 30-example golden set and run it on two prompt versions.
