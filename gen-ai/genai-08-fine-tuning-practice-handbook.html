GPU memory estimate

Rules of thumb for model weights: 16-bit needs 2 bytes per parameter, 8-bit 1 byte, 4-bit 0.5 byte. Full fine-tuning with Adam in mixed precision needs about 16 bytes per parameter for weights, gradients and optimiser state. LoRA adds activations and a small adapter on top of the frozen base.

ModelInference 4-bitQLoRA training (approx.)Full fine-tune (approx.)
3B2 GB6 to 8 GB48 GB
8B5 GB12 to 16 GB130 GB
14B9 GB20 to 24 GB230 GB
32B18 GB40 to 48 GB510 GB
70B40 GB48 to 80 GB1.1 TB

Activation memory depends on sequence length and batch size; gradient checkpointing and shorter sequences cut it. Treat the table as a starting estimate and measure.

QLoRA with Hugging Face TRL

import torch
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig
from trl import SFTConfig, SFTTrainer

base = "BASE_MODEL_ID"            # an instruct model you are licensed to use
bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16,
                         bnb_4bit_use_double_quant=True)
tok = AutoTokenizer.from_pretrained(base)
model = AutoModelForCausalLM.from_pretrained(base, quantization_config=bnb,
                                             torch_dtype=torch.bfloat16, device_map="auto")

peft_cfg = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, task_type="CAUSAL_LM",
                      target_modules=["q_proj","k_proj","v_proj","o_proj",
                                      "gate_proj","up_proj","down_proj"])

ds = load_dataset("json", data_files={"train": "train.jsonl", "validation": "val.jsonl"})

cfg = SFTConfig(output_dir="out", num_train_epochs=2, learning_rate=2e-4,
                per_device_train_batch_size=4, gradient_accumulation_steps=8,
                lr_scheduler_type="cosine", warmup_ratio=0.03, bf16=True,
                gradient_checkpointing=True, logging_steps=10,
                eval_strategy="steps", eval_steps=100, save_steps=100,
                max_length=2048, assistant_only_loss=False)

trainer = SFTTrainer(model=model, args=cfg, train_dataset=ds["train"],
                     eval_dataset=ds["validation"], peft_config=peft_cfg,
                     processing_class=tok)       # "messages" data gets the chat template
trainer.train()
trainer.save_model("out/adapter")

Argument names in TRL and transformers change between releases (for example max_length versus max_seq_length, and processing_class versus tokenizer). Check the docs for the version you install. Set assistant_only_loss=True when your chat template supports it, so the loss ignores prompt tokens.

The same job with Unsloth

from unsloth import FastLanguageModel
from trl import SFTTrainer, SFTConfig

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Llama-3.2-3B-Instruct", max_seq_length=2048, load_in_4bit=True)
model = FastLanguageModel.get_peft_model(
    model, r=16, lora_alpha=16, lora_dropout=0,
    target_modules=["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"],
    use_gradient_checkpointing="unsloth")

trainer = SFTTrainer(model=model, train_dataset=train_ds, processing_class=tokenizer,

Unsloth also ships a web UI (Unsloth Studio) for no-code fine-tuning, plus recipes for GRPO reinforcement learning and long-context training. Verify the model and notebook names against its current docs.

Preference tuning and reinforcement learning

from trl import DPOConfig, DPOTrainer

# model: your SFT model (optionally with LoRA); data columns: prompt, chosen, rejected
dpo = DPOTrainer(model=model,
                 args=DPOConfig(output_dir="dpo-out", beta=0.1, learning_rate=5e-6,
                                per_device_train_batch_size=2, gradient_accumulation_steps=8,
                                num_train_epochs=1, bf16=True),
                 train_dataset=pref_ds, processing_class=tok)
dpo.train()
  • DPO optimises directly from preference pairs without a separate reward model. Use a lower learning rate than SFT and keep beta around 0.1.
  • GRPO and similar RLVR methods sample several answers per prompt, score them with a programmatic reward (unit tests, exact-match, schema validity) and push the model toward better ones. Use when you can verify correctness automatically.
  • Order: SFT first to teach the format, then preference tuning or RL to refine. Re-run the regression suite after each stage.

Gradient checkpointing and accumulationTrade compute for memory

Spot or preemptible GPUs with checkpointsCut cost; save often and resume

For experiment tracking use MLflow or Weights & Biases, and version data and adapters together. See the MLOps handbooks in this library.

Merge, quantise and serve

  • Merge: merged = peft_model.merge_and_unload() then save for a single standalone model. Merge into a 16-bit base, not a quantised one, then re-quantise.
  • Serve adapters separately: vLLM and similar servers support many LoRA adapters on one base model (multi-tenant and per-customer variants share one GPU deployment).
  • Quantise for inference: AWQ or GPTQ for GPU servers, FP8 on recent GPUs, GGUF (Q4_K_M and similar) for llama.cpp, Ollama and edge devices. Re-run evaluation after quantising.
  • Release process: model registry entry, eval report, canary rollout, rollback to the previous adapter, and monitoring of production quality.
# vLLM serving a base model with a LoRA adapter
vllm serve BASE_MODEL_ID --enable-lora --lora-modules support=./out/adapter --max-lora-rank 64
# client: model="support" selects the adapter

Fine-tuning run checklist

  • Baseline: prompted and RAG results measured on the held-out set.
  • Data: cleaned, deduplicated, licensed, split before inspection.
  • Template: identical chat template and system prompt in training and serving.
  • Run: small pilot (1,000 examples) before the full run; log loss, eval and sample generations.
  • Regression: general-ability and safety checks pass.
  • Release: adapter versioned with data and code; canary and rollback plan ready.

Practice

Practice
  1. QLoRA a 3B to 8B instruct model on 1,000 examples of a narrow task and compare with the prompted baseline.
  2. Export to GGUF and run it locally.
  3. Serve the adapter on a vLLM instance and call it by name.
