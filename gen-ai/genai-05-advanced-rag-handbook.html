Step 05 · Intermediate · Beyond naive RAG

RAG Strategies

Naive RAG gets you a demo. Production quality comes from choosing the right retrieval strategy for the failure you actually see. This step catalogues the strategies, shows how each works, and gives a symptom-to-fix map.

Hybrid search with reranking

The most reliable upgrade for most systems is hybrid retrieval followed by a cross-encoder reranker. The bi-encoder embeds query and document separately (fast, approximate); the cross-encoder reads them together (slow, accurate), so it is applied only to the shortlist.

from sentence_transformers import CrossEncoder

def rrf(rankings, k=60):
    """Reciprocal Rank Fusion over several ranked lists of ids."""
    scores = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking):
            scores[doc_id] = scores.get(doc_id, 0) + 1.0 / (k + rank + 1)
    return sorted(scores, key=scores.get, reverse=True)

reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")

def retrieve(query, dense_search, bm25_search, texts, top_n=8):
    candidates = rrf([dense_search(query, 50), bm25_search(query, 50)])[:100]
    pairs = [(query, texts[i]) for i in candidates]
    scores = reranker.predict(pairs)
    best = sorted(zip(candidates, scores), key=lambda x: -x[1])[:top_n]
    return [i for i, _ in best]

Managed rerankers (Cohere Rerank, Voyage, Jina, cloud-provider rerank APIs) are alternatives when you do not want to host a model.

Query transformation

  • Conversation rewriting: turn “what about the enterprise plan?” into a standalone query using chat history. Essential for chat RAG.
  • Multi-query: generate 3 to 5 paraphrases, retrieve for each, fuse with RRF.
  • HyDE: ask the model to write a plausible answer and embed that. Helps when questions and documents use different language, but can inject hallucinated terms, so combine with the original query.
  • Decomposition: split “compare X and Y pricing for EU” into sub-queries, retrieve for each, then synthesise.
  • Routing: a small classifier or LLM picks the index, namespace or tool (docs, tickets, SQL, web).

Smarter chunks

  • Parent-child: index sentences or 200-token children; at query time return the 1000-token parent (or the section). Precision of small chunks with the context of large ones.
  • Contextual retrieval: before embedding, ask a cheap model to write a 1 to 2 sentence description of where the chunk sits in its document, and prepend it. Combined with hybrid search and reranking this materially reduces failed retrievals. Prompt caching makes the ingest cost manageable.
  • Late chunking and long-context embedders: embed the whole document, then pool per chunk so each chunk vector keeps document-level context.
  • Structure-aware parsing: keep tables as tables (Markdown or HTML), keep headings as metadata, and use layout-aware parsers (Docling, Unstructured, cloud document AI) for PDFs and scans.

GraphRAG and hierarchical retrieval

Vector search finds similar passages. It struggles with global questions (“what are the main risks across all contracts?”) and multi-hop questions (“which suppliers share a parent company with the vendor in incident 42?”).

  • GraphRAG: an LLM extracts entities and relations into a knowledge graph, detects communities, and pre-summarises each. Local questions traverse neighbours; global questions use community summaries.
  • RAPTOR style trees: recursively cluster and summarise chunks, then retrieve at the right level of abstraction.
  • When worth it: relationship-heavy domains (legal, supply chain, healthcare, security), or whole-corpus questions. The ingest cost is high because many LLM calls are needed, so measure the gain on your own questions before committing.
  • Stores: Neo4j, Neptune, Cosmos DB Gremlin, TigerGraph, or a graph layer on Postgres.

Agentic and corrective RAG

In agentic RAG the model is given retrieval as a tool and decides how to use it: reformulate, search several sources, read results, retry, then answer. This handles ambiguous or multi-step questions, at the price of latency, cost and less predictable behaviour.

loop (max 4 steps):
    plan   = LLM("what do I still need to know?")
    docs   = retrieve(plan.query, source=plan.source)
    grade  = LLM("are these docs sufficient and relevant?")
    if grade.sufficient: break
    # else rewrite query / switch source / web fallback
answer = LLM(question, context=all_relevant_docs)   # with citations

Keep a hard step budget, log every tool call, and use a simple pipeline when it is good enough. Most enterprise questions do not need an agent.

Multimodal and structured sources

  • Documents with figures and layouts: either parse to text with a vision-language model or embed page images directly with late-interaction models, retrieve pages, and answer with a vision-capable LLM.
  • Tables and databases: use text-to-SQL with a curated semantic layer (descriptions, join keys, metrics), read-only credentials, and result validation. Do not embed rows.
  • Audio and video: transcribe with timestamps, chunk by scene or speaker turn, and keep timecodes as metadata.
  • Code: chunk by syntax (functions, classes), add symbol and dependency graph metadata, and combine lexical search with embeddings.

Rule of thumbAdd one technique at a time and measure on the golden question set. A reranker plus hybrid search plus a good parser solves most problems; the exotic strategies are for the remainder.
