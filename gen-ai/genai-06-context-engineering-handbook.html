Step 06 · Intermediate · Manage what the model sees

Context Engineering

Context engineering is the discipline of deciding what information the model sees, in what order, at each step. As applications grow from single prompts into agents with tools and memory, this becomes the main quality, cost and latency lever.

IntermediateToken budgetsMemory and caching

From prompts to context

The context is everything in the request: system instructions, tool definitions, retrieved documents, conversation history, memory, examples and the user's message. Quality depends on giving the model the smallest set of high-signal tokens that makes the right answer likely.

MoveMeaningExamples
WritePersist information outside the windowScratchpads, notes files, long-term memory stores
SelectPull in only what is relevant, just in timeRAG, tool-loaded files, memory lookup
CompressShrink what is already thereSummaries, trimming tool output, compaction
IsolateKeep contexts separateSub-agents with their own window, sandboxed tools
Context rotMore tokens do not mean better answers. Long, noisy contexts dilute attention, raise cost and make errors harder to trace. Treat the window as a scarce budget.

Token budgeting

BUDGET = 32_000          # target per request, not the model maximum
reserve_output = 2_000
parts = {
  "system + policies":   1_500,
  "tool definitions":    2_000,
  "memory / profile":    1_000,
  "retrieved context":  16_000,
  "conversation":        8_000,
}
assert sum(parts.values()) + reserve_output <= BUDGET
  • Measure real token counts per component in your logs and set alerts when a component exceeds its share.
  • Large tool lists cost tokens on every call: expose only relevant tools per task or load them on demand.
  • Truncate tool outputs (rows, log lines) and return identifiers the model can ask to expand.

Conversation and long-term memory

PatternHowTrade-off
Sliding windowKeep the last N turnsSimple, loses early facts
Rolling summarySummarise older turns and keep recent ones verbatimCheap, summaries can drop detail
Entity and fact memoryExtract user facts and preferences into a store, retrieve per turnPersonalisation across sessions; needs privacy controls and expiry
Episodic memoryStore past interactions or outcomes, retrieve similar onesHelps agents learn from experience
Scratchpad or notes fileThe agent writes plans and progress to external storageSurvives context resets in long tasks

Treat memory as personal data: let users view and delete it, scope it per tenant, and never store secrets in it.

Prompt caching

Providers cache the computed state (the KV cache) of repeated prompt prefixes, giving large discounts and lower latency on cache hits. Self-hosted engines such as vLLM and SGLang offer automatic prefix caching. To benefit:

  • Put stable content first (system prompt, tool definitions, reference documents) and variable content last.
  • Never inject timestamps, request ids or user names into the stable prefix.
  • Keep the order of tools and examples deterministic.
  • Track the cache hit rate as a first-class metric. A low rate usually means the prefix is being changed unintentionally.

Long context versus RAG

FactorLong context (with caching)RAG
Corpus sizeUp to roughly a few hundred pages per requestMillions of documents and beyond
SetupNoneParsing, chunking, index, evaluation
Cost per queryHigh unless the prefix is cachedLow, only retrieved chunks are sent
Recall on needle factsGood but degrades with lengthDepends on retrieval quality
Freshness and ACLsAwkwardNatural: update the index, filter by identity
Whole-document reasoningStrong (summaries, contract review)Weak unless the document is retrieved whole

A common hybrid: use RAG to find the right documents, then load those documents whole into a long context for analysis.

Compression techniques

  • Compaction: when the window nears a threshold, summarise the history, keep decisions, open issues and recent turns, and restart.
  • Tool result clearing: drop old raw tool outputs once their conclusions are recorded.
  • Extractive compression: keep only sentences relevant to the question, using a small model or a reranker score.
  • Structured state: keep a compact JSON of known facts and open tasks instead of replaying the whole transcript.
  • Sub-agent isolation: let a worker read 50 files and return a 300-token report to the parent.

Practice

Practice
  1. Log token counts by component for one real conversation and find the biggest consumer.
  2. Reorder a prompt so the stable prefix comes first and measure the cache hit rate or latency change.
  3. Implement a rolling summary and test that key facts survive 30 turns.
