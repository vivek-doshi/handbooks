Step 07 · Intermediate · Change the model's behaviour

Fine-Tuning Fundamentals

Fine-tuning continues training a pretrained model on your data so that it behaves differently by default: a consistent style, a strict format, a narrow skill or a smaller and cheaper replacement for a large model. This step explains the methods and data; step 08 does it hands-on, and step 12 decides when it is worth it.

IntermediateSFT, LoRA, DPOData first

What fine-tuning does and does not do

Fine-tuning is good forFine-tuning is poor for
Consistent tone, persona and output formatAdding large amounts of fast-changing facts (use RAG)
Domain-specific tasks: classification, extraction, routing, code styleAnything needing citations and provenance
Teaching tool-call and function schemas reliablyPer-user access control
Shrinking a big model into a small, fast, cheap one (distillation)Fixing missing information in the training data
Reducing prompt length by baking in instructions and examplesQuick experiments when prompting has not been tried
The mental modelPrompting and RAG change the input. Fine-tuning changes the weights. Use inputs to supply knowledge and weights to shape behaviour, skills and efficiency.

Methods

MethodWhat it trainsTypical use
Full fine-tuningAll weightsMaximum quality, large GPU memory, needs a lot of data
LoRASmall low-rank adapter matrices added to attention and MLP layers; base frozenDefault for most teams; adapters are megabytes, swappable
QLoRALoRA on a 4-bit quantised base modelFine-tune 7B to 70B models on one GPU
Continued pretrainingAll or most weights on raw domain textNew domain vocabulary and language (medical, legal, low-resource languages)
Supervised fine-tuning (SFT)Learn from prompt and ideal-answer pairsThe standard first step
Preference tuning (DPO, ORPO, KTO)Learn from chosen versus rejected answersStyle, helpfulness, safety, tone after SFT
RL with verifiable rewards (GRPO and similar)Reward correct outcomes (tests pass, answer matches)Reasoning, code and tool-use skills
DistillationStudent imitates a larger teacher's outputsCheaper serving at similar task quality
Embedding and reranker tuningContrastive training on query and passage pairsBetter domain retrieval; often the highest-value fine-tune in a RAG system

LoRA keeps the pretrained weight matrix W frozen and learns an update ΔW = B × A where A and B have a small rank r (commonly 8 to 64). Only A and B are trained, so memory and storage drop by orders of magnitude, and adapters can be merged into W or served separately.

Data: the part that decides the result

Quality beats quantity. A few hundred to a few thousand excellent examples often change behaviour more than 100,000 noisy ones.

# SFT, conversational format (one JSON object per line)
{"messages": [
  {"role": "system", "content": "You triage support tickets."},
  {"role": "user", "content": "Checkout fails with error 500 for EU users"},
  {"role": "assistant", "content": "{\"severity\": \"high\", \"team\": \"payments\"}"}]}

# Preference format for DPO
{"prompt": "Summarise this refund policy...",
 "chosen": "Refunds are available within 30 days...",
 "rejected": "I think there might be some kind of refund..."}
  • Sources: real production traffic (with consent and PII removed), expert-written answers, and synthetic data generated by a stronger model then filtered.
  • Match deployment: use the same system prompt, tool schema and chat template at training and inference. Template mismatch is the most common silent failure.
  • Clean: deduplicate, remove contradictory labels, balance classes, and hold out a test set before looking at anything.
  • Rough sizes: format or style 200 to 2,000 examples; narrow task 1,000 to 20,000; new domain skills far more; preference tuning 5,000 to 50,000 pairs.
  • Licence and privacy: check that you may train on the data, and that the model cannot regurgitate personal data.

Key hyperparameters

ParameterTypical valueNotes
Learning rateLoRA 1e-4 to 2e-4; full fine-tune 1e-5 to 2e-5Too high causes forgetting and instability; use warmup and cosine or linear decay
Epochs1 to 3More epochs overfit small datasets quickly
LoRA rank r8 to 64Higher gives capacity but more memory; start at 16
LoRA alphar or 2rScales the adapter update
Target modulesAll linear layers (q, k, v, o, gate, up, down)Covering the MLPs usually beats attention only
Effective batch size16 to 128 sequencesUse gradient accumulation when memory is tight
Max sequence lengthCover 95 percent of examplesMemory grows with length; pack short examples
Precisionbf16 on modern GPUsfp16 needs loss scaling; QLoRA keeps the base in 4-bit

Watch training and validation loss together. Training loss falling while validation loss rises means overfitting; stop earlier or add data.

Evaluating a fine-tuned model

  • Compare against the strongest prompted baseline, not against the untuned small model. If prompting plus RAG reaches the target, you do not need to fine-tune.
  • Evaluate on a held-out task set that was never used in training, plus an LLM-as-judge or human rubric for open-ended output.
  • Run a regression suite of general abilities (instruction following, safety, a few public benchmarks) to catch catastrophic forgetting.
  • Test on the same prompts, system messages and tools used in production.
  • Track cost and latency per request alongside quality, because efficiency is often the reason to fine-tune.

Common pitfalls

PitfallSymptomFix
Catastrophic forgettingGreat at the task, worse at everything elseLower learning rate, fewer epochs, LoRA, mix in general data
Chat template mismatchGibberish, repeated tokens or ignored instructionsUse the tokenizer's chat template identically in training and serving
Training on the promptModel parrots inputsMask the loss to assistant tokens only
Test leakageExcellent eval, poor productionDeduplicate across train and test; hold out by time or customer
Noisy labelsPlateaus and inconsistent outputAudit samples, cut weak data, tighten guidelines
Tokenizer or EOS bugsNever stops generatingVerify the end-of-turn token is in the training targets
Fine-tuning for factsConfident wrong answersUse RAG for facts, fine-tune for behaviour

Practice

Practice
  1. Write 50 ideal input and output pairs for a task you care about, and test how a prompted model does on 20 held-out ones.
  2. Decide from the results whether the gap is knowledge (use RAG) or behaviour (fine-tune).
