Embeddings and Vector Search

Retrieval is how you give a model knowledge it was never trained on. This step explains embeddings, vector indexes and the databases that serve them, including the memory maths that drives cost at large scale.

BeginnerEmbeddingsANN and vector DBs

What an embedding is

An embedding model turns text (or an image, audio clip or code) into a fixed-length vector so that items with similar meaning land close together. Search becomes geometry: embed the query, find the nearest document vectors.

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-small-en-v1.5")
docs = ["Reset your password from the login page.",
        "Our refund window is 30 days.",
        "GPU nodes are billed per second."]
D = model.encode(docs, normalize_embeddings=True)       # shape (3, 384)
q = model.encode(["how do I get my money back?"], normalize_embeddings=True)
scores = (D @ q.T).ravel()                             # cosine similarity (unit vectors)
print(docs[int(np.argmax(scores))])
ChoiceGuidance
ModelPick from a current benchmark such as MTEB, then test on your own queries. Use the same model for documents and queries.
Dimensions384 to 3072. Matryoshka-trained models let you truncate vectors (for example 1024 down to 256) with small quality loss.
Language and domainUse multilingual models for mixed-language corpora; consider fine-tuning an embedding model for specialised vocabulary (step 07).
Re-embeddingChanging the model means re-embedding the whole corpus. Version the embedding model and index together.

Similarity metrics

MetricMeaningUse
Cosine similarityAngle between vectorsDefault for text; equals dot product on normalised vectors
Dot product (inner product)Angle and magnitudeModels trained for it; fastest
Euclidean (L2)Straight-line distanceSome image and legacy models

Always match the metric the embedding model was trained for, and configure the index with the same one.

Approximate nearest neighbour (ANN) indexes

Exact search compares the query to every vector, which is too slow beyond a few million. ANN indexes trade a little recall for orders of magnitude in speed.

IndexIdeaStrengthsCosts
FlatExact brute forcePerfect recall, tiny datasets and GPU useLinear time
HNSWLayered proximity graphFast, high recall, default in most databasesHigh memory, slower builds and updates
IVFCluster vectors, search the nearest clustersLower memory, good for large setsNeeds training; recall tuned with nprobe
PQ and scalar quantisationCompress vectors to bytes or bits4x to 32x less memorySome recall loss; usually re-rank with full vectors
DiskANN style (disk graph)Graph index mostly on SSDBillion-scale on modest RAMHigher latency, more engineering
Tuning knob to rememberEvery ANN index has a recall versus latency dial (HNSW ef_search, IVF nprobe). Measure recall@k against exact search on a sample, then set the dial to your target, for example 95 to 99 percent.

The memory maths

Raw vector memory is vectors × dimensions × bytes per value, and an HNSW graph adds roughly 20 to 50 percent on top. Do this arithmetic before choosing a database.

Corpus (chunks)Dimensionsfloat32int8 scalarBinary
1 million10244 GB1 GB0.13 GB
100 million1024410 GB102 GB13 GB
1 billion10244.1 TB1 TB128 GB
1 billion256 (Matryoshka)1 TB256 GB32 GB

This is why large-scale systems combine truncated or quantised vectors for the first-pass search with full-precision re-scoring of the top few hundred candidates, and shard the index across nodes.

Selection criteria: scale and growth, filter complexity (multi-tenant ACLs), update rate, hybrid search support, latency target, operational skills, and data residency. Start with the simplest store that fits the next 12 months.

Metadata filters and hybrid search

Pure vector search misses exact terms such as product codes, error ids, names and rare acronyms. Hybrid search runs keyword search (BM25 or sparse vectors such as SPLADE) alongside dense vectors and merges the rankings, typically with Reciprocal Rank Fusion: score = sum of 1 / (k + rank) across the result lists, with k near 60.

-- pgvector example: filtered nearest neighbours
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE chunks (
  id bigserial PRIMARY KEY, doc_id text, tenant text, body text,
  embedding vector(384));
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);

SELECT id, doc_id, body
FROM chunks
WHERE tenant = 'acme'                       -- security and scoping filter
ORDER BY embedding <=> '[0.12, -0.03, ...]' -- cosine distance
LIMIT 10;

Apply access-control filters inside the search, not after it; post-filtering can return empty or leaky results.

Practice

Practice
  1. Embed 200 FAQ entries and test ten paraphrased questions; measure how often the right entry is in the top 3.
  2. Repeat with a keyword-only search and compare. Which questions does each miss?
  3. Calculate the memory for your expected corpus at float32 and int8.
